## Native local state and receive semantics

Actual served functions inspected in Console:

```javascript
function setValueX(a,b){log("["+a+"] "+b);dataValue[a]=b;"string"==typeof b?sendMessage("SETS^"+a+"^"+b):sendMessage("SETD^"+a+"^"+b)}

```

`setValue` invokes `setValueX` for the selected master, then for its stereo partner according to `stereoIndex`; the inspected branch excludes pan/src/scsrc from that partner copy. Native receive splits newline batches; `SETD` invokes `putValue(path, parseFloat(value))`. An identical incoming value would be a no-op in `putValue`. Native `wsock.send(a,b)` attaches Socket.IO ack fields only if `b` is a callback; `sendMessage` calls it without one. These functions do not establish a correlated write acknowledgement.

Separately, pinned `soundcraft-ui-connection` 7.1.0 `index.mjs` around lines 3044 and 3109 merges outbound and inbound into `allMessages$` and feeds its SETD/SETS store from that merged stream; around 3115 the resource-list state uses inbound only. This is implementation evidence that its general store incorporates sent intent, not proof of receipt or a vendor protocol guarantee.
