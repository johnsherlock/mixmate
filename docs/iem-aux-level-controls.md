## Implemented ownership, UI and confirmation

`session-core.js` has a private constructor and literal read-only/control factories; `live-session.js` retains the original four-method read-only API, while `aux-level-session.js` grants only typed level methods. Caller options cannot upgrade the former, and returned snapshots/Maps/targets cannot replace owned observations. The control journal is populated only by the bounded receive parser, with receipt sequence per path, topology/context revision and actual level-change revision (including changes away/back). No raw socket, sender, arbitrary path or public observation updater is returned.

`beginLevelGesture` requires established current-target permission and captures a fresh immutable baseline lease. Commit accepts only its exact opaque token. Selection/context changes invalidate the token before render; group definitions compare a cached stable-profile signature. Opening either connection or group editor clears level context, including Edit Groups from an expanded group. Name/meter/identical-value updates retain the input/cap/preview; actual level or topology changes cancel it and restore received position. Only the selected armed individual input enables. Group master strips remain unavailable with no input/VU.

Cap drag and range keyboard events preview separately from received numeric readouts. Release/key release sends once; double track tap applies once. Single taps, track swipes, generic input/change events, cancelled/lost pointer capture, Escape/focus loss, disabled controls or stale tokens cannot send. Keyboard arrow/Page/Home/End previews use the same token path; no native range event bypasses arming. Extra pointers cancel rather than strand an active gesture. Incoming state never invokes arm or send. After an observed match, permission may persist only on that same selection/context; only a later explicit user gesture recaptures a lease.

Authorization and actual `send()` returns are counted on an operation-local record. The count increments after send returns even if a synchronous callback canceled it, without updating a newer generation's operation. Throwing send delivery is unknown and closes/clears the session; no remaining ordinal is attempted. Reentrant cancellation, native edits or socket replacement prevent the next ordinal. Same-value echoes during dispatch cannot manufacture a correlated ACK; the per-path cutpoint still sits immediately before its own authorization and every target needs later matching receipt.

The 2.5-second confirmation deadline is inspected using dispatch-completed monotonic/wall stamps in snapshots, receive and control entry, as well as a timer. Held timers, delayed packets and backward clocks cannot falsely turn a late echo into observed success. Native wrong values cancel/disarm; expected sequential two-/four-target echoes stay pending until complete. Pending disables all further gestures. Timeout/conflict clears permission without replay; late matching state remains received data and does not rearm.

Main/alias now say Live IEM, with levels OFF/ENABLED/PENDING and a selected-target highlight/accessibly named enable button. Full target/status text stays in title/aria when compact text ellipsizes. No new layout row is introduced. Version 0.4.0 marks the level-capability milestone; the verified worker hash separately identifies exact offline assets. Manifest ID/start/scope remain unchanged. All assets remain local; demo/reference and input test retain separate capabilities.
