## Transport and state semantics

The following archive locators describe **3.5.8328 inline source only**. The external served script and older device's complete bootstrap are not established by it. Selected 3.0 served functions were independently inspected in the earlier report; matching logic is corroboration, not proof the entire bundles are identical.

| Source locator (manifest key) | Static finding and limit |
| --- | --- |
| `socketIoVersion`, `packetEncoder`, `heartbeat` | Embedded Socket.IO 0.9.17, protocol 1. Root-namespace ordinary message packets encode as `3:::<payload>` when no ACK ID is supplied; heartbeat type2 gives `2::`. Other Socket.IO packet types exist, but MixMate supports only its bounded subset. Native transport decodes framing before emitting message payloads. |
| `netInit`, `netStart`, `ioConnect` | Native derives host from document URL, strips mixer/phone page path, defaults port 80, then calls `io.connect` with reconnect settings and `forceNew:true`. Embedded library checks its own `force new connection` option for cache behavior; the call-site spelling alone is not proof of a fresh socket. Global `wsock` and `io.sockets` coordinate connections; MixMate must retain explicit object/generation ownership. |
| `handshake`, `sessionIdAssignment`, `prepareUrl`, `websocketOpen` | In this embedded implementation HTTP GET to `http(s)://host:port/socket.io/1/?t=<time>` obtains colon-separated session ID/heartbeat timeout/close timeout/transports; cross-domain no-CORS branch uses JSONP. First response component becomes `sessionid`, passed to `ws(s)://host:port/socket.io/1/websocket/<sessionid>` (plus query). No generated session ID is established here. No HTTP handshake was captured for served 3.0; its derivation remains **unknown**. None of these candidate requests is newly allowed in MixMate. |
| `ioConnect`, `sendTimeNetwork`, `alive`, `onDataINIT` | Connect callback sends `USERTIME` and `SERIAL`; app startup installs periodic ALIVE and global UI initialization. Data INIT handling requests snapshot/cue lists via current-show state. Source also has receive-error INIT and reconnect paths. These are native side effects, not connection-only permissions or a recovery recipe. Prior3.0 capture saw periodic snapshot/cue list requests; it did not retain all initial setup traffic. |
| `setValue`, `setValueX`, `sendMessage` | Local `dataValue` is assigned **before** send; strings choose SETS, numeric values SETD. `sendMessage` returns connected/send invocation status, optionally adds slave prefix, and calls `wsock.send(payload)` without an ACK callback. Local state can therefore survive absent own receipt. A native connected/send result proves neither application nor readback. |
| `namespaceSend` | Socket.IO ACK fields/callback storage are added only when the second argument is a function. The inspected native setter path supplies none; there is no established correlated parameter-write ACK. Do not infer unsupported ACK/get commands from generic library machinery. |
| `receiveMessage`, `receiveMessage2`, `putValue` | Newline payloads are split; SETD uses `parseFloat`, SETS uses split fields; `putValue` updates/refreshes only when local value differs. Same-value receipt may produce no UI update. MixMate must keep its stricter bounded parser and count actual incoming receipts independently of value changes. Native's merged local map is not an authoritative received journal. |
| `setValue`; GEQ contract locators | Native sends paired masters/output processing individually from link metadata. AUX sends first mirror destination; non-pan/src/scsrc fields may also mirror source links and their destination closure. Pan excludes source-partner copy. This is client fan-out, not server automatic mirroring or safe eligibility validation. Numeric setter concatenates values without general decimal rounding. GEQ31-band setters retain numeric precision. |
| `windowOnload`, `init` | UI globals, storage, event listeners, canvas/resource loading and reload/reconnect behavior are coupled to the bundle. Extracting setter symbols does not create a portable isolated transport dependency. |

Current MixMate differs deliberately: `session-core.js` creates the root WebSocket through `mixerURL`, sends only INIT/ALIVE/heartbeat for connection setup, and accepts callbacks only for its owned socket and generation. Disconnect/hide clears received state; received Ui24/AUX readiness and meter freshness are separate from socket-open. Private parsed observations, per-path receipts/revisions and opaque gesture ownership cannot be replaced by native local state, library store or public presentation Maps. Current policy still requires all-path fresh own receipts within 2.5s, exact values and compatible context; source inspection changes none of it.

Observed 3.0 endpoint `ws://192.168.0.60/socket.io/1/websocket/10815005726458572105` differs from MixMate/peer root `ws://192.168.0.60/`. No controlled endpoint comparison was run. A session-ID/endpoint cause of absent echoes remains a **hypothesis**, not an established fix. Archive handshake evidence does not resolve that causal question.

## What blocks which next step

S02 may proceed after S01 review/merge using an explicit unknown outcome: distinguish actual received observations, requested intent, send return and subsequent observations; bound pending lifetime and define repeated-gesture baselines without converting intent into receipt. Source-backed SETD lacks operation correlation and the captured master demonstrates missing own observations plus precision difference. These are sufficient to reject guaranteed self-echo/ACK assumptions, not to choose universal rounding/tolerance or grant observer authority.

S02 must either leave field-specific precision unresolved/conservative or justify a policy without claiming unmeasured firmware guarantees. If its chosen model requires a getter, INIT refresh, observer socket, endpoint/session replacement, automatic rebaseline or proof that sent intent was applied, the missing exact semantics become a **design blocker for that choice**. Do not invent a read command or add a sender to resolve it.

S03 cannot silently adopt native bootstrap, optimistic received values, generic library transport or unwired GEQ. Any reviewed contract change must explicitly reconcile ADR-0004/5/6 and the current 2.5s rule. S04 needs separately authorized bounded firmware corroboration for the applicable matrix rows (actual precision, own/peer event coverage, native edits, partial/interrupted outcomes and explicit GEQ readiness). Exact served-source gap, endpoint/session cause, server mirroring and pan direction remain parked where needed. F08-S01 still owns both rigs and physical Android/iOS/offline/sleep qualification; targeted tests do not waive it.
