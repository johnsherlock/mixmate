# F07-S06: Install prompt fallback for browsers that don't announce installability

Feature: [F07](../features/F07.md)
Status: **Merged** — [PR #64](https://github.com/johnsherlock/mixmate/pull/64), merge `4c6c574`, final approved head `3a516a3`
Depends on: F07-S05 merged at `5cd755c`; user authorization of the rest of F07 on 2026-11-21 (F07-S06 → F07-S03 → F07-S04)

## User report (2026-11-21)

On a Pixel (Android 17, Chrome 157.0.8103.78) neither Chrome nor Brave showed the "Install MixMate" strip. Brave installed the app from its menu; Chrome's menu said "This app cannot be installed". Root confirmed with Chrome DevTools `Page.getInstallabilityErrors` (desktop and Android UA) that the deployed build has no installability errors, so this is most likely that phone's Chrome state or the same-origin Chromium issue 572287931/568841400 (hypotheses). The strip only waited for `beforeinstallprompt`, which Brave never fires and Chrome fires only when it thinks the page is installable.

## Decisions (root; also in [user follow-up](../user-follow-up.md))

1. Not installed and no `beforeinstallprompt` within **3 s** of load: the same non-modal strip shows menu instructions, no Install button. Android: "To install: open your browser menu (⋮) → Install app or Add to Home screen". iOS/iPadOS keeps "To install: Share → Add to Home Screen" immediately.
2. A later `beforeinstallprompt` switches the strip to the real Install button.
3. Same per-device dismissal; hidden when installed or after `appinstalled`; the × stays enabled with aria-label "Dismiss install prompt" and title "Dismiss". Diagnostics install state reads "Menu instructions: …".
4. One injectable timeout (no polling), cleared on event, install and destroy.
5. Version 0.6.1 (patch) with CHANGELOG entry.
6. Post-merge docs for F07-S05 folded in; Pixel finding recorded in follow-ups and [device checks](../device-checks.md).

## Decisions beyond the brief (story agent)

- **Desktop:** the generic line "To install, use your browser's install or Add to Home screen option, if it has one" shows only on non-Android, non-iOS devices that report touch points (tablets, "desktop site" modes, touch laptops). A plain desktop (no touch points) shows nothing: MixMate is a phone/tablet app, desktop browsers surface their own install affordance, and a permanent hint to Firefox desktop users would be noise. Touch laptops may see the line; accepted.
- After the user taps Install, the fallback never returns for that page load, so an accepted prompt cannot flash the menu line before `appinstalled`.
- A dismissal made earlier applies to the fallback too (one key); Diagnostics "Show install prompt" re-shows it.

## Review round 1 (PR #64 at `453ed15`: independent reviewer APPROVE with P3s; root live acceptance)

Root's Chrome device emulation on a Mac (Android UA, `navigator.platform` "MacIntel", `userAgentData.platform` "Android", 5 touch points) showed the iOS line immediately because `isIOS()` treated MacIntel + touch as iPadOS. Fix: an Android UA or `userAgentData.platform === 'Android'` is never iOS (the iPadOS heuristic applies only to non-Android agents), and the Android instruction also keys on `userAgentData`. Test added with exactly those values (Android fallback after 3 s) and a real iPadOS case (MacIntel, 5 touch points, Safari UA) still getting the iOS line. Version stays 0.6.1 (unreleased).

## Acceptance criteria

- Android UA, not installed, no event: strip with the menu instruction at 3 s, not before; no Install button.
- Standalone, installed, dismissed: nothing. iOS unchanged.
- Late event: Install button enabled; `prompt()` only on tap.
- Timer cleared on destroy/event/install; buttons enabled through `mountReadOnlyView`; accessible names kept.
- CI `version-check` passes at 0.6.1.

## Validation

Fake timers, window, navigator, storage and DOM only; no mixer contact. `tests/f07-s06-install-fallback.test.js` (7 tests); existing F07-S05 install tests unchanged. `npm test` 530/530 (523 before), `npm run build` passes (18 assets). Real Pixel retest is not run by the story agent (F08-S01).
