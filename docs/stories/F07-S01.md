## Outcome and scope

Verify snapshot list/recall/save protocols under ADR-0002 user authorization. Document exact narrowly scoped message forms, operation identifiers, types/ranges, capability/state prerequisites, confirmation, success/readback and interruption behavior; update active allowlist and guards in the reviewed implementation without a repeated feature-class permission request. This story delivers the contract, pure serializers/parsers, the typed guard in the private session owner and a private API with fake-transport tests. **No UI** (F07-S02) and no live-desk actuation by the story agent.

## Evidence

Root, 2026-11-21, desk Ui24R firmware 3.0.7865-ui24: native `mixer.html` source and `E_COMMANDS`, a hooked native UI (read-only menu open) and a Node WebSocket script limited to show `Default` and snapshots MixMate1/MixMate2. Recorded in full, with per-socket delivery, and separated into source-backed / observed / untested, in the [snapshot contract](../iem-snapshot-contract.md#evidence). Summary: `SNAPSHOTLIST^<show>` replies to the requester only; `LOADSNAPSHOT^<show>^<name>` gives the requester `MSG^$SNAPLOAD^<name>` and everyone `UPDATE_SHOWS` plus (only when it changes) `SETS^var.currentSnapshot^<name>`, then the changed values; `SAVESNAPSHOT^<show>^<name>` gives `UPDATE_SHOWS` only; locks apply only when `settings.block.pass` is non-empty. Not tested: show/delete/rename/save-as, other snapshots, lock behaviour.

## Decisions (root, routine; also in the [follow-up log](../user-follow-up.md) and [ADR-0009](../adr/0009-snapshot-operation-contract.md))

1. Exact forms on the control session writer socket only; everything else excluded.
2. Typed names-only API (`requestSnapshotList`, `recallSnapshot(name)`, `saveCurrentSnapshot`); show always the received `var.currentShow`; recall names must be in the latest fresh received list; save targets only the received current snapshot; names bounded (64 chars / 256 bytes), no `^` or control characters; `* Init *` never.
3. Prerequisites revalidated at send: qualified writer and companion, a received show, a fresh list, no gesture or pending own send (refuse, never cancel the drag), one operation outstanding, desk locks. **Beyond the brief:** unknown lock state refuses; the password value is reduced to "is set" at parse time and never stored.
4. Bounded writer-receive parser for exactly `SNAPSHOTLIST^<show>^…` and `MSG^$SNAPLOAD^<name>` feeding only the list and outcome, never mixer/provider/meter state. `UPDATE_SHOWS` stales the list.
5. Outcomes: recall `confirmed` (writer MSG or companion `var.currentSnapshot` equal to the name, 5 s) / `unconfirmed`; save `reported` (companion `UPDATE_SHOWS`, 3 s, wording says it proves only a show-change report) / `unconfirmed`; `unknown` on disconnect/hide/failure; no retry, replay or rollback.
6. F02-S05 rig following unchanged.

## Implementation notes

- `src/iem/snapshot-protocol.js`: encoders, name/show validators, `parseSnapshotWriterFrame`, `parseSnapshotCompanionFrame` (separate parser, so lock data never enters the observed map).
- `src/iem/session-core.js`: private snapshot state and API gated by the `auxControl` literal factory flag; one new send site, whose static audit in `tests/build-offline.test.js` now expects two `message` sends.
- Beyond the brief: a list request is read-only and may run while a previous operation is outstanding; a list reply racing an `UPDATE_SHOWS` is stored stale; a list request not answered within 5 s is dropped so it can be repeated; the `settings.block.*` INIT line form was unrecorded, so SETD and SETS are both accepted and an unparsed lock means a refusal. **Closed 2026-11-21:** root read the raw INIT lines: `SETS^settings.block.pass^<string>` (empty on this desk) and `SETD^settings.block.<x>^0|1`, which matches the parser.

## Acceptance criteria

Listing is distinguished from mutation; exact commands and side effects are verified and reviewed under ADR-0002; the named snapshot recall/save exception does not permit arbitrary scene/configuration write paths; cancellation and disconnect behavior are defined; no mock snapshot labels become live facts.
