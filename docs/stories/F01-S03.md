# F01-S03: Device compatibility and transport gate

Feature: [F01](../features/F01.md)
Status: Awaiting device evidence — draft PR #9
Depends on: F01-S02B (discovered selector-label correction; F01-S02 and F01-S02A already merged)

## Outcome and scope

Collect bounded read-only mixer observations, prepare and execute the device matrix with the user, and record support verdicts and any required architecture decision.

## Acceptance criteria

Capture provenance includes app commit/build, OS/browser versions, rig and installed/browser context; Android Chrome, iPhone Safari and iPad Safari installation, offline cold launch, permission, state receipt, sleep/reopen and offline update recovery have explicit results; untested devices remain unverified; blockers have a documented resolution or explicit user-approved scope change. No parameter writes are used.

## Validation and delivery

- Follow repository AGENTS.md and ADR-0001. Keep changes scoped to this story.
- Use fake mixer transports for automated tests; never automate real parameter writes.
- Run `npm test` and `npm run build` before opening a PR. Add meaningful checks for the behavior changed.
- Record automated results separately from device observations. Never mark a hardware gate passed without evidence.
- One story branch and PR; request `@codex review`, fix findings and request review of the final revision.
- Merge only with passing required checks and affirmative Codex review applicable to the final changes. Silence or a local agent self-review is not approval.
- Update story/feature/backlog status and evidence links in the story PR; do not begin the next story until this PR is merged.
