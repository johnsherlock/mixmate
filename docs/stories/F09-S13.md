# F09-S13: Move Create/Edit Group next to All Groups

Feature: [F09](../features/F09.md)
Status: In review — branch `codex/f09-s13-group-button-order`, app 0.10.1
Depends on: F09-S12 merged ([PR #69](https://github.com/johnsherlock/mixmate/pull/69), `c8dab46`); user request of 2026-11-22.

## User request (2026-11-22)

"Let's move 'Create/Edit Group' to the right of 'All Groups'."

## Decision

1. With an AUX selected the row reads: All Mixes, group shortcuts, **All Groups, Create/Edit Group, All Channels**, Mix EQ. `renderShortcuts` (`src/iem/live-view.js`) moves the existing `[data-action="edit-groups"]` node into `.mm-group-switches` immediately after All Groups. The node is never recreated, so its editor click listener, label (Create Group / Edit Group), `aria-label`, disabled state and `data-group-action` are unchanged.
2. **Where All Groups is not shown** (overview, no AUX selected; the shortcut row is hidden): the node returns to `.mm-local-tabs` after Mix EQ, its previous place, so it stays reachable.
3. Layout: the button joins the existing shortcut flex row, so it inherits that row's wrapping (portrait), single-row nowrap/ellipsis (compact) and the 26 px ultra-compact button height (the existing `.mm-navigation button` rule). No new CSS. Root checks 375 px portrait, tablet and compact landscape live.
4. Version 0.10.1 (patch) with CHANGELOG entry. No wire, allowlist or behaviour change; the Demo is unchanged.

## Acceptance criteria

- DOM order in group views: All Groups, immediately followed by Create/Edit Group, then All Channels; it follows All Groups with or without an expanded group.
- Create Group opens a new group; Edit Group opens the expanded one (unchanged).
- Overview keeps the button after Mix EQ.
- No overflow at 375 px portrait, tablet or compact landscape.

## Validation

`npm test`, `npm run build`; fake DOM only, the desk was not contacted.
