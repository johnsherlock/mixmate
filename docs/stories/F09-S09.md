# F09-S09: EQ panel cleanup, immediate GEQ reset and prototype pan presentation

Feature: [F09](../features/F09.md)
Status: In review — PR pending on `codex/f09-s09-eq-cleanup`; independent review, CI and root live acceptance pending
Depends on: F09-S08 merged at `9527f91` (`9527f91e6f00fdaaa0fc4f3f34471f312501c47e`, PR #54); user feedback and decisions of 2026-11-20

## User feedback (2026-11-20)

After testing F09-S08 the user reported:

1. The live EQ panel shows text under the graph that is not in the prototype: the status line, the Points help, the legend, the "Approximation: band centres…" note, the **Band readback** disclosure and the requested row. Remove it from the default UI.
2. The ↺ reset button asks for confirmation ("Reset bands / Keep bands"). It should simply reset.
3. The live pan dialog shows debug text: the "Last requested (inactive): …" readout, the "Ready to edit…" status, the Details disclosure, the "Normalized position only…" note and the per-output received rows. The dialog and the strip Pan buttons should match the prototype/Demo, with L/CENTRE/R values.

## Decisions

1. **EQ diagnostics only with `?debug`.** Like F09-S07's Details, `mountEqControls` receives live-entry's tested `debugFlag()` value. Without it, the status, mode notes, legend, approximation note, band readback disclosure and requested row are never created, so they take no layout space. The panel is the head line plus graph/sidebar, and the graph fills the freed height.
   - Essential read-only state is one compact, ellipsised line in the EQ head (`.mm-live-eq-state`), for example "Read-only · L/R GEQ unequal", "Read-only · waiting for bands", "Read-only · output link unknown", or the owner's one-line reason. The full text is in its title, the graph's aria-label and the app's existing header/footer status. The head hint and state badges are `role="status"` live regions when `?debug` is off.
   - The sidebar's "Shelves / cuts: unverified · not available" note stays (it is part of the sidebar, not text below the graph).
   - Dead CSS (the reset confirmation row) is removed; the diagnostic CSS remains for `?debug`.
2. **Immediate reset (user decision 2026-11-20).** One ↺ click calls the private owner's existing typed scoped reset (`resetEqBands`): sparse (bands already at 0.5 are not sent), both sides of a verified equal pair, bypass/filters untouched, never native `resetGraphEQ`, never streamed. Points re-anchor at 0 dB as before.
   - A gesture active at the click is cancelled first (the existing behaviour), so its live steps stay applied. The owner then refuses the reset while it cannot arm (for example while its own echoes are outstanding); nothing is queued or replayed.
   - A second click before the echo, or with every band already at 0.5, sends nothing.
   - An auto-repeated Enter keydown on the button is suppressed, so one click is at most one reset.
3. **Prototype pan dialog.** Title `MIX · CHANNEL · PAN` (received AUX name, else `AUX n`), labels LEFT / CENTRE / RIGHT, a large `L 30` / `CENTRE` / `R 30` readout, the full-width slider (`aria-valuetext` "Pan L 30"), presets Hard L / Centre / Hard R and the footer "Fine control · full-width travel".
   - The readout, slider and `aria-valuetext` show this owner's requested value only while its gesture or own echoes are live (the strip button's rule), else the shared received value, else `—` (unknown or unequal sides). Review P1: after an unechoed preset and the 2.5 s window the retained requested chain is no longer shown. Re-review P1: "live" means the session's current-gesture preview (`previewPan`) or a pending own send — `gestureActive` alone does not count, because begin emits before any preview with the retained request, and the gesture/arrow start is read from the slider. Level caps show the retained request consistently before and at begin (the F09-S03 rule, no snap) and start from received after select-away; groups and GEQ rebase on received after the window (F09-S06).
   - When pan is read-only the footer becomes a compact reason ("Read-only · L/R pan unequal", "Pan not received", or the owner's reason), with the full status in its title. It never flashes during the owner's own dispatch.
   - The raw "Requested/Last requested" line, the status and Details (with the per-output received rows) render only with `?debug`.
4. **Strip Pan button.** `PAN · L 30` / `PAN · CENTRE` / `PAN · R 30`. The source uses the received actual pan on the selected output (`panWire`, one exactly equal value for a verified pair) or this owner's requested value while its pan gesture or own echoes are live (dashed outline, `data-pan-requested`). Unknown or unequal shows just `Pan`. Ultra-compact strips drop the `PAN · ` prefix.
5. **Display mapping (user decision 2026-11-20).** Wire 0 = `L 100`, 0.5 = `CENTRE`, 1 = `R 100`, linear and rounded to an integer, symmetric about centre, in `src/iem/pan-display.js`. The text follows the Demo's `panLabel` convention ("CENTRE", "L 30"), which the user allowed instead of "C". This supersedes the AGENTS.md "no direction labels" rule for display only. Wire values are unchanged, and root verifies the physical direction on the desk against the native app.
6. **Unchanged.** Pan write semantics (typed guard, strict 0..1, three-decimal normalization, live throttled gesture, presets 0/0.5/1 as deliberate one-shots through the existing path); GEQ wire forms, allowlist and guards; the private writer plus receive-only companion and own-echo rules; keyed nodes and touch rules; Demo isolation and `mockups/iem.html`.
7. **Accepted F09-S08 doc leftovers fixed.** ADR-0008 and `iem-relative-groups.md` no longer say silent anchors/groups are unavailable (F09-S08: silent members are valid anchors). F09-S08 decision 3 now says the near-handle grab is mouse-only; touch uses the handle-owned r=24 hit circle.

## Acceptance criteria

- Without `?debug` the live EQ panel renders only the head and the graph/sidebar: no status line, notes, legend, approximation note, band readback or requested row, and no page scroll introduced at desktop, tablet, phone portrait or landscape. With `?debug` they appear as before.
- Unequal L/R, incomplete bands or unknown links show one compact line in the EQ head; the graph, sliders and buttons keep their aria-labels.
- One ↺ click sends the sparse reset at once (L/R pair as today); a second click before the echo or with all bands at 0.5 sends nothing; a click during a gesture cancels it first and never queues; Enter autorepeat cannot repeat it. No confirmation UI exists.
- The pan dialog shows `MIX · CHANNEL · PAN`, LEFT/CENTRE/RIGHT, the large L/CENTRE/R readout, the full-width slider, Hard L / Centre / Hard R and the footer; raw values, status and Details only with `?debug`.
- Strip Pan buttons show `PAN · L n` / `PAN · CENTRE` / `PAN · R n` from received actual (or the live requested value during this owner's gesture), and `Pan` when unknown or unequal.
- Wire 0 / 0.5 / 1 display as `L 100` / `CENTRE` / `R 100`; presets still send 0 / 0.5 / 1.

## Validation

Fake transports and fake timers only.

- GEQ tests: default UI creates no diagnostics and shows the compact head state and aria labels; one-click sparse L/R reset, a second click and an all-flat click send nothing; reset during a keyboard gesture cancels it first and sends only the scoped reset; Enter autorepeat is suppressed; live entry passes `debug` to the EQ and pan views; no confirm CSS remains. Existing diagnostic tests mount with `debug: true`.
- Pan tests: mapping (0/0.25/0.5/0.75/1, symmetric rounding, invalid values) and the Demo convention; default dialog title/labels/readout/presets/footer, Hard R/Hard L one-shots with unchanged wire values, unequal sides read-only with the compact footer; strip button actual/requested/unequal labels. Existing diagnostic tests mount with `debug = true`.
- Review P1 test: an unechoed Hard R preset, window expired → dialog readout, `aria-valuetext`, slider and strip show the received `L 50`.
- Re-review P1 tests: after the expired window, begin keeps the slider at 0.25, a left cap drag and an ArrowLeft step write values below 0.25 (never the retained 1); unequal sides keep the slider at the first received side; level begin keeps its shown start.
- `npm test` 436/436 pass; `npm run build` passes.
- Root live desk checks (2026-11-20) passed for strip buttons, pan presets, EQ panel and reset; wire 0 = left confirmed against the native app.
- Browser layout was not checked by the story agent: the live EQ and pan dialog need a connected session, and no desk or mixer connection was used. The CSS change only removes content below the graph, whose `flex: 1` (portrait: the Demo's fixed graph row) already takes the freed height.
