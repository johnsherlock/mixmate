# F09-S05: Live throttled control writes, live group preview and full-range group travel

Feature: [F09](../features/F09.md)
Status: In review — [PR #51](https://github.com/johnsherlock/mixmate/pull/51); user-directed independent review approved `f5687c7`; live post-fix group re-test passed; merge pending
Depends on: F09-S04 peer runtime and F06-S04 GEQ runtime merged; explicit user decision of 2026-11-18

## Outcome and scope

User-reported bugs on a phone with the live desk: (1) moving a group fader did not move member faders until release, then they jumped; (2) the group fader was a fixed ±12 dB relative window and never reached "loudest at max" / "quietest at min"; (3) native-app moves appeared smoothly in MixMate, but MixMate moves reached the desk/native app only on release.

The user explicitly chose (2026-11-18) to **reverse the release-only rule**: send changes continuously while dragging, throttled, for channel/master faders, group faders, pan and EQ. This story implements that decision and records it in [ADR-0008](../adr/0008-control-state-model.md#current-f09-s05-live-write-decision--2026-11-18), [ADR-0004](../adr/0004-aux-level-safety.md#f09-s05-live-writes--2026-11-18), AGENTS and the runtime/level/group/pan/EQ contracts. Feature-class authorization, exact wire forms, allowlist and literal factories are unchanged: only the timing of already-allowlisted typed writes changes.

## Acceptance criteria

- Throttled live writes during a deliberate cap/key/preset gesture: leading step immediately, then at most one step per 50 ms (level, group, pan) or 120 ms (GEQ) carrying the latest cached preview; no queue of stale steps. Release sends the final exact value only if it differs from the last step. GEQ reset stays a confirmed one-shot.
- Every step goes through the private owner: reducer `stream` event, then the existing per-ordinal guard (writer+receiver open/current, generation, topology, canonical settings, exact authorization); reentrant receipt rules still apply; no generic sender. Receipts, selection, settings and track scroll/swipe never write.
- Sparse requests for every kind (≥1e-9 from the last requested value), so the desk echoes each step.
- Own echo versus native: a companion receipt equal, exactly or at the desk's 10-significant-digit format, to a value this owner authorized for that path within 2.5 s and not yet superseded is an own echo (no cancel; raw actual updates). Any other changed receipt is native and stops the stream immediately; no rollback/replay; the next deliberate gesture uses current actual.
- Group live preview: member strips show the requested common-delta values (dashed caps, "Group requested …"), separate from received level text; linked pairs move together.
- Full-range group travel: the cap starts at the loudest member's position and moves along the fader law; top puts the loudest member at 1, bottom puts the quietest at the −100 dB floor (never position 0); one common clamped delta; Δ shown.
- Interruption: socket failure stops immediately, keeps touched-closure recovery, no retry; applied steps may remain.
- Keyed nodes, touch rules, phone layouts, `textContent`, demo isolation and the read-only/level-only factories are preserved.

## Design summary

- **Reducer** ([control-state-model.js](../../src/iem/control-state-model.js)): `stream` event creates a `live` operation from the current preview without ending the gesture, superseding a pending previous step as `sent-unverified`. Sparse planning and chain-coordinate merging now apply to every kind. The gesture freezes `baseDelta`/`origin` so streamed steps (which update the chain) never compound. Peer states keep a bounded own-echo journal (recorded at each `authorize`, pruned after 2.5 s, consumed in order). A group never re-anchors while own echoes are outstanding.
- **Session** ([session-core.js](../../src/iem/session-core.js)): `scheduleStream`/`streamStep` throttle via the injected timers; `commit` cancels the pending step and sends the final preview; reset previews without streaming. Begin keeps the full scope check; in-gesture preview/step/commit and live dispatch revalidate topology only, because linked own echoes arrive as separate receipts (native value changes are caught by the reducer per receipt). The active gesture's target stays eligible/editable for the UI while echoes land. Group previews take the loudest-member reference position; the owner converts it to a delta against its own frozen anchor.
- **Group travel** ([relative-groups.js](../../src/iem/relative-groups.js)): `GROUP_FLOOR_DB = −100`, `groupTravel`, `groupReferenceDelta`, `groupReferencePosition`; `GROUP_DELTA_WINDOW` removed. Floor rationale: one common dB delta cannot reach −∞ evenly, and the −199 dB finite anchor window would reject a near-silent member after desk rounding; −100 dB (position ≈ 0.00125) is visually the bottom and re-anchors normally.
- **UI**: group input 0..1 with the loudest-member start (gestures re-read the cap start after begin), member live preview, copy now says changes are sent live; EQ/pan/connection notes updated.
