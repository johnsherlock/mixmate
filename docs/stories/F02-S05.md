## User decisions (2026-11-20)

Source: user decision in orchestrator conversation. These supersede conflicting AGENTS/doc wording, updated in this PR.

1. **Rig identity is the desk's current snapshot name**, exact case-sensitive match after the same trimming used on store. Once `var.currentSnapshot` is received, the stored rig with that name is loaded, or one is created with empty groups. **Follow live:** a changed `var.currentSnapshot` while connected switches to (or creates) the matching rig, cancelling gestures, selection and group context like the old profile change, but keeping the socket. An empty, missing or invalid name means no rig; groups are unavailable with a one-line reason. Rig names are copied from the received name (rendered as text) and validated for length and control characters; an invalid name is no rig, never a mangled one. Offline, Edit Groups uses the last-used rig.
2. **Rig UI removed.** The live Connect dialog is a mixer IPv4 address field and Connect, plus Disconnect when connected, Close and feedback. No saved-rig picker, rig name, New rig or Save rig. The current snapshot name is shown read-only in `.mm-snapshot-name` (and `.mm-native-snapshot`), otherwise "Unavailable". Snapshot list/recall/save stay unwired (F07).
3. **Known addresses.** Every private IPv4 address that reached received Ui24 readiness (not socket-open) is stored, most recently successful first, capped. Manual success adds or promotes. Addresses are not rig identity.
4. **Automatic connection** (overrides "connect only by explicit user action, no automatic reconnect"): on app open, after an unexpected drop, and when the app returns from sleep/background (visible again, `pageshow`, or `online`), try each known address in order with a short per-attempt timeout, stopping at the first that reaches Ui24 readiness; if all fail or none exist, open the Connect dialog. One pass per trigger; no probing while connected or while the Connect dialog is used; an explicit Disconnect never triggers automatic reconnection until the next app open or explicit Connect. Attempts never overlap; an explicit Connect cancels an in-flight pass. Only the live IEM app (`index.html`/`iem.html`) auto-connects.
5. **Discard existing rigs/groups.** Settings document version 3: profiles `{ id, name, groups, navigation }` (no address), a known-address list, no `localDefinitions`. v1/v2 migration discards old profiles, groups and device-local definitions and may seed known addresses from old profile addresses. Preferences, atomic transaction/conflict semantics, strict validation and the never-persist rules are unchanged.
6. `connection-test.html` / `src/main.js` is adapted minimally to v3 (known-address suggestions, manual address); it does not import input writers into AUX control.

## Routine decisions (story agent, for review)

Recorded in [user follow-up](../user-follow-up.md).

- **Known-address cap: 8**, most recent first, deduplicated. Enough for a few venues/rigs and both common defaults; a stale address costs at most one attempt each.
- **Per-attempt timeout: 5 s** (`AUTO_CONNECT_ATTEMPT_MS`). A LAN INIT normally qualifies in well under a second; 5 s tolerates a slow tablet without making a two-address pass feel stuck. The session's own 15 s deadline still applies to manual connects.
- **Rig cap: 128** (was 32 hand-made profiles). **Overflow:** creating a rig at the cap removes the first stored rig that has **no groups** and is not the last-used rig (only its saved view is lost). If every rig holds groups, nothing is removed: the new snapshot has no rig and the status says "Groups unavailable: 128 snapshot rigs with groups are already stored on this device." Never silent group loss. Reset local settings (Settings / test) clears everything.
- **Drop loop guard:** a drop within 30 s of an automatic reconnection (`AUTO_RECONNECT_MIN_INTERVAL_MS`, raised from 10 s after review so it covers the session's 15 s qualification and 30 s idle deadlines) opens the Connect dialog instead of starting another pass.
- **Drop definition:** a connection that had reached `live` and then ends `closed`, `error` or `timeout`. Hiding, pagehide, navigation and explicit Disconnect end as `disconnected` and are not drops. A failed manual attempt that never qualified is not a drop.
- **Opening the Connect dialog cancels a pass** and retires an in-flight attempt that has not yet qualified, so nothing connects behind the user.
- **Other dialogs pause automatic work** (review P2-2): while Edit Groups, pan, EQ or channel detail is open, a pass never starts a new attempt, never retires a slow one and never ends; it resumes (and deferred triggers or the deferred Connect dialog run) when the last dialog closes. Automatic attempts do not bump the context revision unless a selection existed, and losing a connection that never received state does not bump it either, so an open editor and its draft survive.
- **Status-line notices** (review P3-1): "No known desk address answered" and "dropped again soon" also show in the status line until the next connection, so they are visible when the Connect form is closed.
- **Rig-creation failure** is forgotten when the received snapshot name changes (review P3-2).
- **Readiness = full qualification** (review P2-1): session phase `live` (received Ui24 model plus a non-matrix AUX level) **and**, for the two-socket control session, an open writer. Sessions now report this as `qualified` in their snapshots. A companion that qualifies while the writer never opens is not success: nothing is recorded, it is not a drop, and the attempt times out after 5 s. The same definition gates address recording and drop detection.
- **During connect, before the name arrives**, the last-used rig stays bound (no churn when it matches); a qualified connection without a name has no rig.
- **Follow-live view:** a switched-to rig with a saved mix restores it; otherwise the current AUX selection stays and the group view resets.
- **Address field edits no longer disconnect** a live session (they are not identity); Connect stays disabled while connected.
- **Migration address order:** the previously selected profile's address first, then profile order.
- **Connection test** never records addresses (its `MixerConnection` does not verify Ui24 AUX readiness) and never auto-connects. A legacy `mixmate-address` value seeds the known-address list only on first use.
- The session cancels obsolete control intent itself when `var.currentSnapshot` changes after a previous value (reason `profile`), in addition to the controller's owner change.

## Acceptance criteria

- v3 schema validates strictly (unique ids and exact names, trimmed names, ≤128 rigs, ≤8 unique private addresses); v1/v2 migrate on read without writing, discarding definitions and seeding addresses; newer versions stay untouched.
- Receiving a snapshot name binds or creates the rig; a changed name switches while the socket stays; invalid/empty/missing names give no rig with a reason; disconnect clears the displayed name and falls back to the last-used rig offline.
- Automatic pass ordering, per-attempt timeout, readiness-not-socket-open, single pass, dialog fallback, no overlap, explicit Disconnect suppression, wake/visible/online/drop triggers and cancellation by explicit Connect or dialog use.
- Known addresses promoted on success and capped.
- No new outbound message; demo isolated; connection test manual.

## Live acceptance (root, pending)

- Open the installed/live app with a known address: it connects automatically without the dialog; with a wrong first address it moves to the next after about 5 s; with none reachable the Connect dialog opens once.
- The header shows `IMGL FIBBERS` (or the current snapshot); Edit Groups opens a new empty rig for it; groups saved persist across reload.
- Recall another snapshot in the native app while connected: the header and groups switch without reconnecting; recalling the first snapshot returns its groups.
- Disconnect explicitly, background/foreground the app: no reconnection. Lock/unlock the tablet after a live session: one automatic pass reconnects.
- Old saved rigs/groups are gone after the update (expected); preferences remain.
