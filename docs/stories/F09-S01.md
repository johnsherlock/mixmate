## Outcome and scope

Establish a versioned native protocol reference and decide the transport/dependency boundary before changing control behavior. Default to a small owned adapter with native code as evidence; evaluate native internals and community helpers by their actual roles rather than transplanting a client.

## Acceptance criteria

- Index relevant served native source privately in ignored local storage with version, hash, origin and source locators recorded in repository documentation. Read source as text; do not bundle, execute or reuse vendor runtime code by default. Record provenance/licensing limits and reproducibility if private artifacts are unavailable.
- Describe actual framing, endpoint/session setup, send/receive paths, current-socket provenance, local requested state and precision/mirroring behavior. Separate the served 3.0.7865 source/trial from other firmware archive evidence. The native local-first setter has no established correlated ACK callback.
- Audit soundcraft-ui-connection 7.1.0: current live imports supply display conversion; MixMate owns its WebSocket and control session. Trace derived meter/relative math and reference evidence separately. Compare helper-only retention, owned adapter and native dependencies, including native global UI, reconnect and startup USERTIME/SERIAL/list requests; these are not implicitly permitted setup commands.
- Build a bounded evidence matrix for master, source-send, relative-group, eligible pan and proposed GEQ multi-write behavior. A single paired-master trial does not verify those other rows. Distinguish observed facts, source-backed claims, unknown endpoint/session causality and hypotheses.
- Identify which unresolved facts block the state contract versus later firmware qualification. No guessed read command, new writer, automatic hardware test or unbounded capture. Any future live check needs separately recorded bounded session authorization.
