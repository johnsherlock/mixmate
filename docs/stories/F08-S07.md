# F08-S07 — Wire the Nudge view to live AUX levels

Feature: [F08](../features/F08.md)

Status: App 0.12.0 merged in [PR #74](https://github.com/johnsherlock/mixmate/pull/74) at `a9165f5`, final approved head `b344797`, [CI passed](https://github.com/johnsherlock/mixmate/actions/runs/45445199743). Physical phone and desk acceptance is parked.

Design: [F08-S06](F08-S06.md), approved by the user on 2026-11-24.

## Outcome

A performer can adjust the current AUX mix mid-song with the approved Nudge cards and return to the same fader view.

## Acceptance criteria

| Where the performer taps **Nudge** | Controls shown, in order |
| --- | --- |
| All Groups, the group-master fader view | The selected AUX master, followed by every group master for the current rig and mix |
| An expanded group | The selected AUX master, followed by every group master for the current rig and mix, then the channels in the expanded group in their saved order |

- Keep the approved equal-sized, colour-coded cards, with the target name and current fader dB on one line. Group dB shows the loudest member's level using the existing group readout rules. Preserve the existing stereo readback and unavailable-value conventions.
- Each deliberate minus or plus tap makes one adjustment through the existing typed level controls, using the configured nudge steps, level limits and target eligibility. Group nudges apply one common relative delta to the saved members under the existing anchor and receipt rules. The session owner remains responsible for stereo qualification and dispatch.
- Show unavailable targets with disabled buttons and a reason. A disconnect, AUX change, group change or rig recall must invalidate obsolete targets before another tap can send. Opening, closing, scrolling and incoming updates send zero writes. **Faders** returns to the originating view while its context remains valid.

## Validation

- Use fake mixer transports to verify both target lists, return navigation, each nudge target class and direction, disabled and stale targets, and zero writes from passive interactions. Check that each valid tap uses only the existing allowed level paths for that target.
- Verify tap usability and actual readbacks on a phone with the desk. Record the build, device, firmware and observations.
- Follow the [presentation contract](../iem-presentation.md), [AUX level controls](../iem-aux-level-controls.md) and [relative group controls](../iem-relative-groups.md). Run the required tests and build and follow the repository's versioning and review workflow.
