# F01-S02A: Correct the installed app identity

Feature: [F01](../features/F01.md)
Status: Done (merged)
Depends on: F01-S02
Discovered during: F01-S03 device checks

## Problem and scope

The manifest declared `id: "./"`. Unlike `start_url` and `scope`, the manifest ID is resolved against the start URL's origin. The deployed ID therefore identifies `https://johnsherlock.github.io/`, rather than the MixMate app at `/mixmate/`. The S02 production test incorrectly resolved all three fields against the manifest directory and missed this defect.

Set the stable ID to `mixmate/`, which resolves to `https://johnsherlock.github.io/mixmate/` under the manifest processing algorithm. Keep `start_url`, scope, service-worker and asset paths relative to the existing `/mixmate/` deployment. No transport, controls, mixer permissions, layout or gestures change.

The user reports Pixel 6 Pro Chrome offers “already installed” / Open, but the app is absent and Open does nothing; a Lenovo 9-inch tablet installs successfully. Versions, offline launch and received live-state results have not been supplied. The identity defect is confirmed, but a causal link to the Pixel behavior is unproven.

## Acceptance criteria

- A regression test first reproduces the origin-root ID defect against the previous manifest.
- Production manifest ID resolves against `start_url.origin` to `/mixmate/`, distinct from the origin-root identity and another app's ID, and stays stable if MixMate's start URL changes within its scope.
- Existing relative start URL, scope, icons and offline inventory checks continue to pass.
- Document the identity migration and a targeted MixMate-only retest; do not claim the Pixel is fixed before user evidence.
- `npm test` and `npm run build` pass; one PR receives affirmative `@codex review` before merge. Preserve the uncommitted handoff unchanged.

## Migration and device gate

Browsers that honor manifest IDs can treat the corrected identity as a separate app, rather than an in-place update of the old root identity. Existing MixMate installations may need a targeted uninstall/reinstall after the corrected deployment is live. Record the current installation details first; remove only an identifiable MixMate app, never another app, all Chrome data or unrelated site storage. Uninstall may remove installation-local data; F02 backup/export is not yet implemented.

After deployment, close MixMate windows, reopen the online app URL and complete the normal install flow. If Chrome still offers Open with no identifiable installed MixMate, collect Android Settings → Apps and `chrome://webapks` details before further recovery. Do not blindly remove an app that may own the old root identity.

F01-S03 remains awaiting device evidence in draft [PR #9](https://github.com/johnsherlock/mixmate/pull/9). Rebase that evidence branch after this corrective story merges, then retest Pixel and Lenovo against the corrected deployment. Android offline/live and all iPhone/iPad verdicts remain unverified.
