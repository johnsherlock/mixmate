# F01-S02B: Follow received names in the input selector

Feature: [F01](../features/F01.md)
Status: Implementation complete; awaiting Codex review and merge
Depends on: F01-S02A
Discovered during: F01-S03 device checks

## Problem and scope

The user reports reaching the mixer after correcting the Ethernet cable connection. The installed app shows a received channel name in “Your channel,” but its input dropdown still shows only Channel 01–24. The exact device/installed context remains ambiguous; this observation does not establish mobile/offline compatibility or qualify a platform.

`src/main.js` creates the 24 options once and previously never refreshed their labels. Update those existing options from received current-socket names during rendering: `Channel 01 — <received name>`, retaining the numbered fallback when a name is missing or empty, or the connection is no longer live. Received mixer names are not persisted in documentation, fixtures or settings.

## Acceptance criteria

- All 24 existing option elements retain their values, order and selected channel. Option labels follow received names, including unselected channel updates/native renames.
- Missing/empty names use numbered fallbacks. Disconnect, hiding and a fresh connection show no previous-session names.
- Names are assigned only through `textContent`; markup and special characters remain literal text.
- Rendering incoming names cannot send parameter writes, change the selected channel, arm/disarm an otherwise valid selection or change transport/write permissions.
- Actual app-entry regression tests use fake DOM/options and fake sockets. They cover all labels, partial initialization, clearing, fresh reconnect, identity/value/selection preservation and absence of outgoing SETD/SETS.
- Run `npm test` and `npm run build`; one corrective-story PR receives affirmative Codex review before merge. Do not merge F01-S03 as a completed compatibility gate.

- Fixture names are synthetic; no actual received desk names are recorded.
- No real mixer access, parameter writes, protocol/allowlist, layout or touch-gesture changes. The uncommitted handoff remains unchanged.
