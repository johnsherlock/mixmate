# F01-S02C: Show offline version and update notices

Feature: [F01](../features/F01.md)
Status: Done — merged in PR #12
Depends on: F01-S02B
Requested during: F01-S03 device checks

## Outcome and scope

The user confirms the tablet has verified offline version `917e3ba9d64587ec` and the named selector works. They request an alert when the app updates. This is a targeted update/name check, not a cold-offline, sleep or platform qualification; OS/browser versions and other device results remain pending.

Show the actual verified active worker/cache hash as **Offline version** beside existing offline readiness. Provide separate accessible in-app notices for (a) a downloaded waiting update and (b) a different activated version that successfully verifies against a previously verified version. These are nonmodal page notices, not system push notifications.

## Acceptance criteria

- First verified observation silently records the baseline; same-version reopening never claims an update. A changed valid hash announces only after successful current-controller verification.
- A namespaced guarded device-local version marker stores no mixer state. False/failed/timed-out verification does not advance history. Corrupt/blocked storage keeps readiness/version display usable; if saving history fails, suppress historical update alerts rather than repeat them on each reopen.
- A waiting installed worker, observed at startup or through updatefound/statechange, shows: “Update downloaded. Close all MixMate windows/tabs when finished to use it.” It does not become the current version or announce activation. Failed/superseded workers cannot claim a download/update.
- Observer callbacks are bounded by registration preparation and obsolete listeners/results are cleaned up or ignored. Notices never call skipWaiting, reload, activation, mixer disconnect or reconnect.
- Preserve accepted mockup, responsive layout and touch gestures. Existing mixer transport and permission scope do not change.
- Fake service-worker/app-entry tests cover baseline, changed/same versions, failed/timeout verification, unavailable/corrupt storage, existing/new waiting workers, failures, overlap and an uninterrupted fake mixer connection.
- Run `npm test` and `npm run build`; request affirmative Codex review before merge. F01-S03 remains draft/incomplete.
