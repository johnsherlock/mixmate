# F09-S02: Reviewed control state and confirmation model

Feature: [F09](../features/F09.md)
Status: Design/pure model prepared — pending affirmative final-change review, CI and merge
Depends on: F09-S01 merged

## Outcome and scope

Write and review an ADR and executable pure model for control ownership, uncertainty and repeated gestures that fits the evidence without assuming self echoes. This story decides the model; production behavior stays unchanged until F09-S03.

## Acceptance criteria

- Distinguish owned received observations, requested intent, send return, unknown delivery and later observations. Do not call matching observations correlated acknowledgements. Define field-specific precision policy from evidence; numerical tolerance must not conceal native changes.
- Define missing/partial/stale/conflicting observations, native edits (including away/back), generations, reentrant callbacks, context changes, interruption, explicit cancellation and reconciliation. Preserve no retry, replay or rollback and non-atomic multi-write disclosure.
- Define authority and safe finite baselines for repeated individual, linked and relative-group gestures, including silent members, deduplicated paths and whole-move clamp. Requested intent must never silently become received state or proof of application.
- Evaluate observer sockets, reconnect, getters and INIT refresh separately as alternatives with evidence and authority limits; do not preapprove a second socket, optimistic received state or guessed request command.
- Define honest pending/requested/actual UI, deadline and recovery outcomes without a permanent pending deadlock. Cover 31/62-path GEQ scalability and native changes without enabling GEQ writes.
- Pure fake tests exercise the proposed transitions and invariants. Review explicitly reconciles any proposed changes with existing level/pan/EQ contracts; current 2.5-second fresh per-path confirmation remains authoritative until reviewed F09-S03 integration.
