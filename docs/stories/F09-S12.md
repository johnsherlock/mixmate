# F09-S12: UI tweaks — All Groups, Create/Edit Group, group dB readout, nudge buttons, FX names, fader fill, wider snapshot name

Feature: [F09](../features/F09.md)
Status: In review — branch `codex/f09-s12-ui-tweaks`, app 0.10.0 (PR number and merge record added by root)
Depends on: F06-S05 merged ([PR #68](https://github.com/johnsherlock/mixmate/pull/68), `c1bfe3f`); user request of 2026-11-22 after testing on real devices.

## User request (2026-11-22)

1. Add an **All Groups** button to the left of **All Channels**; it returns to the main group fader view, the same as unselecting/collapsing a group.
2. Rename **Edit Groups** to **Create Group**. Clicking it always opens the group editor on a **new** group.
3. When a group is **expanded**, that button becomes **Edit Group** and opens that group in the editor.
4. The dB reading on the **group faders** "doesn't really make much sense. It always reads 0.0 dB".
5. **Nudge controls on every fader** (group, channel/source send, AUX master): up and down buttons side by side, with arrows, below the dB reading. Up raises the level by **+3 dB**, down lowers it by **1.5 dB** (user's values, 2026-11-22; a group nudges every member). The user wants to tweak these values, so they live in one place: [`src/iem/nudge-config.js`](../../src/iem/nudge-config.js), constants `NUDGE_UP_DB = 3` and `NUDGE_DOWN_DB = 1.5`.
6. **FX return names** show "FX return N — unnamed", but the native app shows "FX1 Reverb, FX2 Reverb, FX3 Delay" etc.
7. **Fader fill:** colour the fader track from the bottom up to the cap, like the native app: yellow for most faders, **light blue for FX** sources.
8. The **header snapshot name** is cut off on phone and tablet ("ALTERNATIVE A…" on the user's tablet). Make its box about **50% wider**, without overlapping the clock.

## Evidence (root, Ui24R firmware 3.0.7865-ui24, 2026-11-22)

- `f.<n>.name` is received empty for all four FX returns (`f.0..3.name=`).
- The desk also sends `f.<n>.fxtype` as `SETD` numeric: f.0 = 0, f.1 = 0, f.2 = 1, f.3 = 3.
- Native source (the desk-served `mixer.html`): `E_FX = {REVERB:0, DELAY:1, CHORUS:2, ROOM:3}`. An FX strip's default label is `lang.FX + " " + (index + 1)` plus the type name when the name is empty ("FX 1 REVERB"); the user writes it "FX1 Reverb".
- MixMate's `observedName` fell back to "<label> — unnamed" ("FX return 1 — unnamed").

## Decisions (root; also in [user follow-up](../user-follow-up.md))

1. **All Groups:** a navigation button immediately left of All Channels in the existing shortcut row, shown wherever All Channels is shown. It calls the new `controller.allGroups()`, which does exactly what collapsing the expanded group does (`chooseNavigation({ view: 'groups', expandedGroupId: null })`, saved as navigation only) and writes nothing; it is a no-op when already on the group fader view. Active (`aria-pressed`) when the group fader view is current (`view === 'groups'`, no expanded group).
2. **Create Group / Edit Group:** one header button (`data-action="edit-groups"`). With no group expanded it reads **Create Group** (`aria-label` "Create a new group") and opens the editor on a new empty group; with a group expanded it reads **Edit Group** (`aria-label` "Edit group <name>") and opens that group. The editor's group catalog selector, "+ New" and Delete stay. `mountGroupEditor().open(id)` now opens a NEW group when no id is given (it used to default to the expanded or first group); the bound button handler passes the expanded group id. Existing tests that relied on the old default were updated to pass an id.
3. **Group readout:** the group strip shows the **loudest member's received displayed level** (where the cap sits), formatted like the level text ("−12.0 dB", "−∞ dB"). During a group gesture or while its own steps/echoes are live it shows the loudest member's **requested** preview level (`control.groupReference`). "—" when no member level is known. The always-0.0 "Δ" text and its spans are gone; it is not a received group level or hardware-balance claim (tooltip/`aria-label` say so).
4. **Nudge buttons:** two side-by-side ▲ / ▼ buttons (`.mm-nudge`) in the strip head directly below the value readout on every live level fader (group, source send, AUX master); fixed height, so strip geometry never changes during drags. Accessible names are built from the constants: "Raise <name> by 3 dB" / "Lower <name> by 1.5 dB" (with " (unavailable: <reason>)" when disabled). Semantics in the existing display scale:
   - channel/master: ±N dB from the current displayed level; **up from −∞ (or anywhere in the bottom segment) goes to the −70 dB floor**, **down that would land below −70 dB goes to −∞** (desk position 0), clamped at +10 dB;
   - group: one common display-scale delta ±N applied exactly like a group fader move from the loudest member (the cap), clamped at the first member limit by the unchanged private owner (top: loudest at max; bottom: quietest at position 0); a member at −∞ is a valid anchor that can rise.
   - **Write path:** each press is one deliberate gesture through the existing typed level/group gesture API: `onBegin` (same selection, `canEditLevel` and refusal handling as a cap), `previewLevelGesture(target position)`, `commitLevelGesture`. All guards apply unchanged (per-ordinal guard, throttle, own-echo classification, native change cancels, pair equality, recovery barriers, `updateBusy`). The leading step sends once; the commit sends nothing further when unchanged. No new outbound message, no allowlist change, no auto-repeat on hold, and only a `click` triggers it (pointer travel over the buttons is not a gesture; the cap/track gesture code is untouched). A refusal shows the existing one-line reason ("Level not changed: <reason>") in the status line and the message slot.
   - Disabled with a reason (title and accessible name) when the fader is not editable (no control/connection, unequal or read-only linked targets, unresolved or unknown level, echo wait, another target dispatching).
5. **FX names:** the received parser accepts `f.<n>.fxtype` (receive-only; `SETD` integers 0–3, anything else unknown and ignored). A received **empty** FX name displays `FX<n+1> <Type>` with Type Reverb / Delay / Chorus / Room, or `FX<n+1>` when the type is unknown; a received non-empty name wins; a name never received stays "name not received". `textContent` only. IDs remain `f.<n>`, so saved groups are unaffected. No new outbound message.
6. **Fader fill:** pure CSS on the existing range track (`::-webkit-slider-runnable-track` / `::-moz-range-track` gradient) driven by `--mm-fill` (the 0..1 cap ratio), which `gestures.sync()` writes in the same pass as the cap position, so drag previews and every orientation/compact layout follow with no layout change or extra reflow. Colour variable `--mm-fill-colour`: the Demo/app yellow (`--mm-yellow`) for inputs, line, player, AUX masters and groups; light blue (`#7fd0f5`) for FX returns (`.mm-strip[data-fx="true"]`). The exact native yellow was not sampled from the desk (not contacted); the existing UI yellow is used.
7. **Snapshot name width:** the header snapshot column is 50% wider on the landscape grids (default 90–170 px → 135–255 px; ≤900 px 80–140 → 120–210; ≤700 px 95 → 143). **Phone portrait (≤480 px):** the second header row cannot give the box +50% beside the four utility buttons (name area was 134 px of 167), so the snapshot takes the full row (name area 322 px) and the utilities move to a third row, right-aligned; the clock stays alone on row 1. Tablet portrait already had far more room and is unchanged. Checked in a browser harness (fake model, no mixer): 375 px portrait, 568×320 and 667×375 landscape (snapshot ends 5 px before the clock, name area 110 px, was ~64), 1024×768 landscape (name area 222 px, was 137, no overlap).
8. **Version** 0.10.0 (minor) with CHANGELOG entry.

## Acceptance criteria

- All Groups sits immediately left of All Channels, returns to the group fader view, is active there, writes nothing and fits 375 px portrait and compact landscape.
- The header button reads Create Group (opens a new empty group) or Edit Group (opens the expanded group); accessible names are accurate.
- The group readout is the loudest member's level (received, or requested preview during a gesture, "—" unknown); no 0.0 dB Δ text.
- Every live level fader has ▲/▼ buttons below the readout with the stated semantics, built from `nudge-config.js`; each press is one gesture with the unchanged guards and the same outbound SETDs as an equivalent fader move; disabled/refused states give a reason; no write from scroll/touch.
- Unnamed FX returns show `FX<n> <Type>` (Reverb/Delay/Chorus/Room), `FX<n>` for unknown type; a received name wins.
- The track is filled from the bottom to the cap, yellow, light blue for FX, following drag previews.
- The snapshot name box is about 50% wider without overlapping the clock.

- `tests/iem-navigation.test.js` (+2): `allGroups()` returns to the group view, persists only navigation, no outbound message; Create/Edit Group editor entry.
- Updated deliberately: `tests/iem-groups.test.js` and `tests/iem-navigation.test.js` (editor opens with an explicit id), `tests/iem-presentation.test.js` (group readout, shortcut count/order), `tests/iem-fader-feel.test.js` (the Δ container rules are gone).
- `npm test` 601/601 pass (was 584); `npm run build` passes (four entries, 18-asset worker).

## Beyond the brief

- Phone portrait header reflow (decision 7) to reach the requested width.
- `controller.allGroups()` is a no-op when already on the group fader view (no extra settings write).
- A nudge of an already-at-limit fader (+10 dB up) begins and commits a gesture that sends nothing (equal retained vectors are no-ops).

## Risks and open items

- Exact native yellow/light-blue not sampled; colours are the UI's own yellow and `#7fd0f5` (one-line CSS change).
- The 14.5 px fill stop assumes the 29 px WebKit thumb; Firefox's 27 px thumb is within 1 px.
- The snapshot width and the nudge row were checked in a desktop browser harness, not on a physical phone/tablet; F08-S01 remains the device gate.
- Compact landscape loses about 22 px of fader travel per strip to the nudge row (layout kept; travel remains usable at 667×375).
