# F09-S06: Fader feel, dB-linear level scale and robust GEQ echo handling

Feature: [F09](../features/F09.md)
Status: In review — [PR #52](https://github.com/johnsherlock/mixmate/pull/52) on `codex/f09-s06-fader-feel-and-eq`; independent review, CI and root live acceptance pending
Depends on: F09-S05 merged at `7d8a8cb` (PR #51); user report and decision of 2026-11-19

## User report (2026-11-19)

Screen recordings on desktop Chrome against the dev server, desk firmware 3.0.7865-ui24:

1. Dragging any level fader (single channel or group) was very jerky in MixMate, with the UI visibly redrawing, while the native app followed smoothly (so the wire writes were fine).
2. The group fader moved members "in some sort of ratio". The user wants every member to travel the same amount and stop when the first member reaches max (up) or min (down), like moving several faders with one hand. The Demo behaves exactly right.
3. GEQ points mode "barely nudges" the three points. Draw mode works well and stays as it is.

## Root cause and decisions

1. **Layout shift during drags.** In wide layouts the strip state line (`.mm-live-strip-state`) had no fixed height, wrapped, and was shown or hidden as `data-actionable` toggled with every pending live step. It also carried full-precision raw values ("Requested 0.5523…"). The header/footer status text re-wrapped the header row as its length changed. The fader space, the range input height and the cap position therefore changed mid-drag, and the pointer mapping used the changing height. Every step also ran a full render with per-fader forced layout.
2. **Scale mismatch, not a ratio.** The group logic already applied one common dB delta, but live faders showed the raw desk position, whose law is strongly non-linear in dB (0.8 → +1.3 dB, 0.3 → −26.8 dB, 0.1 → −52.9 dB). Equal dB moved loud faders far and quiet faders little, and the −100 dB floor dropped everyone ~73 dB to bunch at the bottom. **User decision (2026-11-19): live level faders use a Demo-style dB-linear display scale**, accepting that low-level cap positions will not visually match the native app.
3. **Dropped/coalesced desk echoes blocked GEQ editing.** Root's live probes (writer plus separate receive-only socket, one band path): every isolated change is echoed to the companion; re-sending the value the desk already holds gets no echo; two writes 0–5 ms apart that return to the previous value get no echo at all; writes ≥20 ms apart are each echoed; a burst at 10 ms gaps drops the intermediate. A points gesture whose last write was never echoed left a received-basis record that only a matching receipt could clear, so after the chain was lost every later gesture was refused ("Waiting for the desk to report the last EQ change … reconnect to refresh"). Points drags also froze when any band would exceed ±15 dB because the whole requested curve was rejected.

## Acceptance criteria

- No geometry change in a strip or the header during a gesture: one fixed-height, single-line, ellipsised strip state line in every live layout (toggled by visibility, never display/height); header feedback and footer status single-line with flex basis 0; mode label fixed minimum width; strip value readout single line. Requested levels in the strip are formatted dB with one decimal; raw values stay in the title and Details.
- Reduced per-step work: session-driven redraws during an owned gesture coalesce to one per animation frame (immediate render when the gesture ends); cap sync reads all rects before writing; gesture travel is measured once per drag.
- Live level faders (source sends, AUX masters, group masters) use the dB-linear display scale; the wire value stays the desk position through the unchanged typed guards and allowlist. Ticks +10/0/−12/−24/−40/−60/−∞ replace the "POSITION" label (compact layouts keep hiding the ruler). Pointer resolution 0.1 dB; arrow keys 0.5 dB.
- Individual faders can still reach desk position 0 (−∞); received levels below −60 dB display in the short bottom segment without being rewritten.
- Groups: equal dB = equal distance for every member; cap starts at the loudest member; top = loudest at desk position 1; bottom = quietest at −60 dB; a member already below −60 dB gives zero downward travel; a group never writes position 0.
- A missing echo never blocks editing indefinitely: a received-basis wait (GEQ/group) is bounded by the 2.5 s observation window from the last write; afterwards the next gesture builds on received actual and the status says the desk did not report the change and MixMate is using the desk's reported values. Own-echo matching (≤128 values/path) still absorbs coalesced intermediates; any other changed value still stops a stream. No invented receipts, replay, rollback or requested-as-actual.
- GEQ points: a dragged point's single gain Δ is clamped to the largest magnitude keeping every band within ±15 dB (one common parameter limit, never per-band clipping), so the handle stops at the limit and still follows horizontally. Draw mode is unchanged.
- Pan and GEQ sliders, keyed nodes, touch rules, phone portrait three-column banks, compact landscape layouts, Demo isolation, literal factories and the private writer + receive-only companion are unchanged.

## Design summary

- **Display scale** ([fader-scale.js](../../src/iem/fader-scale.js)): scale units are dB. +10…−60 dB is linear in dB over about 93% of travel; the bottom 5 scale units (−60…−65) map desk position linearly from the −60 dB position (1/17) down to 0 (−∞). `positionToScale`/`scaleToPosition` use the existing continuous fader law; position 1 ↔ +10 exactly. [live-view.js](../../src/iem/live-view.js) converts at the boundary: the session still previews/commits desk positions and returns clamped positions.
- **Group floor** ([relative-groups.js](../../src/iem/relative-groups.js)): `GROUP_FLOOR_DB = −60` (equal to the scale floor); travel, reference delta and clamping are otherwise unchanged.
- **Bounded basis wait** ([control-state-model.js](../../src/iem/control-state-model.js)): basis records carry the completion time of the newest overlapping write; `pruneBasis` drops records older than the observation window and sets `unconfirmed` when any member had no newer receipt. [session-core.js](../../src/iem/session-core.js) schedules one timer at the earliest basis/own-echo expiry so the UI re-renders without another event, and adds the status note. Incomplete-dispatch recovery barriers (S04) are deliberately unchanged: an interrupted send still needs complete post-floor receipts or an explicit reconnect.
- **Point clamp** ([aux-eq-curve.js](../../src/iem/aux-eq-curve.js) `clampPointGain`, used by [eq-controls.js](../../src/iem/eq-controls.js)). The private session contract is unchanged: it still rejects, never clips, an out-of-range requested curve.
- **Render/gesture cost**: [live-controller.js](../../src/iem/live-controller.js) frame coalescing; [gestures.js](../../src/iem/gestures.js) batched sync, cached travel, `data-key-step`.

## Validation

Fake transports and fake timers only. New `tests/iem-fader-feel.test.js` (scale mapping/round trips/−∞, group −60 floor and equal-dB travel, member below −60, bounded group basis wait with automatic re-render and native cancel, cached gesture travel and 0.5 dB keys, frame coalescing, CSS geometry rules) and new GEQ tests with a probe desk modelled on the live probes (reversal within 5 ms gets no echo; same-value resend gets no echo; coalesced intermediates; foreign value still cancels; point clamp unit and UI; EQ view re-enables at the window). Updated expectations, all intentional: presentation tests now assert dB-scale input values/ticks and formatted strip text (raw value in title/Details); the S05 group basis test checks the wait before the window instead of after it; the GEQ "unechoed write" test now asserts blocking within the window (its after-window behaviour is the new rule); status regexes follow the new "Waiting up to 2.5 s …" copy.

Local Node 26.13.1 (CI Node 24): `npm test` 417/417 pass (405 before; 12 new); `npm run build` passes. A loopback browser check on the Vite dev server with a stubbed in-page WebSocket (no desk) confirmed the dB ticks, cap positions and constant fader/input heights while dragging. No hardware, desk or device was touched.

## Needs live acceptance (root, story-scoped standing permission)

- Smooth level and group drags on desktop Chrome and a tablet; no visible redraw/jump; header does not re-wrap.
- Group: equal travel for all members; top stops at loudest = max; bottom stops at quietest = −60 dB; member below −60 dB blocks downward travel.
- Individual fader reaches −∞ (position 0) at the bottom of travel.
- GEQ points: repeated gestures, including quick reversals and release right after a step, never stay blocked beyond ~2.5 s; status explains the unconfirmed case; handle stops at ±15 dB and follows horizontally.
- Native edit during any MixMate drag still stops the stream.

Physical Android/iOS/offline/sleep qualification remains [F08-S01](F08-S01.md).
