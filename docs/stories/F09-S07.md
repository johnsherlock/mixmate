# F09-S07: −70 dB fader floor, cleaner live strips and persistent GEQ points

Feature: [F09](../features/F09.md)
Status: Merged — [PR #53](https://github.com/johnsherlock/mixmate/pull/53) at `dc371cb` after independent review approval of `54c50cd`, passing CI and root live acceptance (PR record). The −70 dB group floor was superseded by F09-S08 (to −∞).
Depends on: F09-S06 merged at `50e24d5` (PR #52); user report and decisions of 2026-11-20

## User report (2026-11-20)

The user tested F09-S06 on the desk (firmware 3.0.7865-ui24) and reported:

1. Group drags stop the quietest member at −60 dB; the user expects −70 dB.
2. The per-strip state overlay at the bottom of each live channel strip (for example "Live changes are sent while you drag…") is not in the design, and its changing text makes the UI jitter during a drag.
3. The per-strip **Details** button is not in the design.
4. GEQ Points mode does not behave like the Demo's persistent parametric points.
5. In compact landscape the group Δ readout truncates ("Δ +10.4…").

## Root cause and decisions

1. **User decision (2026-11-20): floor −70 dB.** The dB-linear display span becomes +10…−70 dB (`FADER_SCALE_FLOOR_DB = −70`, `FADER_SCALE_MIN = −75`, so the short bottom segment to −∞ keeps about 6% of travel) and `GROUP_FLOOR_DB = −70`. The desk fader law is unchanged; −70 dB is desk position ≈0.0252 (> 0), so a group still never writes position 0.
2. **Strip state overlay removed.** The overlay re-rendered text on each live step. Live strips no longer render it (source and group strips), and the group strip's bottom note ("Last requested gesture Δ" / "Live Δ · sending while you drag") is removed too. The text survives only as the fader space's `title` tooltip (attribute only, so it never changes layout) and in the debug-only Details. The single-line header and footer status are unchanged.
3. **Details is development-only.** The per-strip Details button renders only with `?debug` (for example `index.html?debug`). Without the flag, Pan spans the strip footer like the mockup. `channel-detail.js` and its dialog are unchanged; detail models are now keyed by strip, not by button.
4. **Root's live finding (2026-11-20, the real bug).** In Points mode the FREQ and WIDTH sliders sent nothing ("Unchanged requested coordinate; no commands sent") because every point's gain reset to 0 after each release (a "relative Δ that returns to 0 after each release"). A point therefore had no lasting identity: a boost could not be moved to another frequency or have its width changed, and the GAIN slider snapped back to 0. **User decision (2026-11-20): points behave like the Demo's.** There are three persistent points (x, gain, narrowness), and the curve is a base plus the sum of their bumps. Moving FREQ moves the bump, and bands it leaves go back down.
5. **Compact group readout.** The group readout is a fixed "Δ " prefix span plus an amount span; compact landscape hides the prefix, so "+10.4 dB" fits. Group fader geometry is unchanged.

## Acceptance criteria

- Live level faders are dB-linear from +10 to −70 dB with a short bottom segment to −∞. Ticks are +10/0/−12/−24/−40/−60/−70/−∞, and compact layouts drop the −∞ label rather than overlap −70. Individual faders still reach position 0.
- Groups: the bottom of travel puts the quietest member at exactly −70 dB (never position 0). A member already below −70 dB allows no downward travel. The top still puts the loudest member at position 1 (+10 dB).
- Live source and group strips render no state line or bottom note. Nothing is re-rendered per pointer move in a way that changes layout. Status stays in the header/footer and the tooltip.
- With no `?debug` there is no Details button, and Pan alone fills the strip footer. With `?debug`, Details works as before.
- GEQ points: an in-memory anchor holds the base (session coordinate in dB, captured when point editing starts) and persistent {x, q, gain} for each point. Every points gesture requests `requestedPointSamples(points, base)` through the unchanged private session GEQ API (sparse, throttled, same own-echo rules). Gains persist across releases; handles sit at base + bumps; sliders and the GAIN Δ readout show persistent values.
- The anchor is re-captured (base := current coordinate, gains := 0, x/q kept) on panel open or output change, after a draw gesture or confirmed reset, on connection/context change, and at gesture begin when the coordinate differs from the last requested base + bumps beyond the 10-significant-digit echo rounding or 1e-9 epsilon. An outside change shows "Curve changed on the desk; points restarted from the current curve."
- Saturation is unchanged. A point's own centre stops at ±15 dB, computed from the base plus the other points' persistent bumps. Other bands clip at ±15 per band, and a points request is never rejected whole. Handle and slider gain per point stay within ±12 dB. Draw mode and the session still reject an out-of-range curve whole.
- With all gains at 0, a FREQ/WIDTH change sends nothing, and the status says so plainly. Draw stays exclusive, and switching modes sends nothing. Reset stays a confirmed one-shot.
- The compact landscape group Δ readout does not truncate.
- Unchanged: wire forms, allowlist, literal factories, private writer + receive-only companion, keyed nodes, touch rules, phone portrait three-column banks, Demo isolation and the `mockups/iem.html` reference.

## Design summary

- [fader-scale.js](../../src/iem/fader-scale.js) and [relative-groups.js](../../src/iem/relative-groups.js) set the floor constants. [live-view.js](../../src/iem/live-view.js) tags ruler ticks (`data-tick`) for the compact −∞ rule.
- [live-view.js](../../src/iem/live-view.js):
  - It takes a `debug` option, and [live-entry.js](../../src/iem/live-entry.js) sets it from `?debug` (plus `data-debug` on the root).
  - `setState` only sets the fader space title and the Details text.
  - The group readout uses prefix and amount spans.
- [iem.css](../../src/iem/iem.css):
  - Dead `.mm-live-strip-state` rules are removed.
  - Pan spans the footer (`inset: auto 3px 2px 3px`), and only `[data-debug]` leaves room for Details.
  - Compact rules drop the −∞ label and the Δ prefix.
- [eq-controls.js](../../src/iem/eq-controls.js):
  - Point state is now `anchor = { base, interrupted }`, with `reanchor`/`dropAnchor`/`anchorMatches`.
  - The match check maps the persistent points over the base with `mapRequestedAuxEqCurve` and compares against the session coordinate. A band matches if it is within 1e-9 or equal after 10-significant-digit formatting. The same rules live privately in `control-state-model.js`, which only `session-core.js` may import.
  - A cancelled points gesture keeps its points and marks the anchor interrupted: if the curve still matches at the next begin, nothing restarts; otherwise a neutral "interrupted" status is shown. A draw (committed or cancelled) or reset drops the anchor.
- [aux-eq-curve.js](../../src/iem/aux-eq-curve.js): comments only; `requestedPointSamples` and `pointCentreGainLimit` are unchanged.

## Review fixes on `6de49dc` (2026-11-20)

- **Hint never masks owner status (P2-1).** A local restart/no-op hint is shown alongside the owner's reason/status, never instead of it.
- **Render-time re-anchor (P2-2).** With no gesture active, when the editable coordinate no longer matches base + bumps, the points restart (gains 0) with the plain status. The editable coordinate is the requested values while own echoes are pending, else complete equal received bands once the owner allows editing, so pending echoes never trigger a restart. The check is suppressed while begin/finish run.
- **Interruptions (P3-3).** A failed or partial release marks the anchor interrupted, as a cancel does, so the status says "interrupted", not "changed on the desk".
- **Debug flag (P3-5).** `?debug=0/false/no/off` does not enable debug (`debugFlag`).
- **Screen readers (P3-6).** Strip status is mirrored into a visually hidden span referenced by the fader's `aria-describedby`.
- **Tick labels (P3-8).** Ruler labels never overlap: the ruler is a size container, and below about 11 px of spacing the −∞ label is dropped first (travel < 190 px), then −70 (< 95 px).
- **Group readout (root 1280×800 finding).** The readout box is an inline-size container: below 104 px it drops the "Δ " prefix, and below 80/64 px it shrinks the amount to 12/10 px. Box and fader geometry are unchanged.
- **Group footer kept (P3-7).** The group strip keeps its 24 px bottom padding. Member strips reserve it for the Pan row, and removing it would make the group fader travel and ruler longer than the members' in the same bank, so their tick scales would no longer line up.
- **Tests (P3-4).** Added tests for cancel with matching and mismatching curves, pending own echoes, the owner ending a gesture mid-drag (reason shown next to the hint, restart once editable), the render-time restart, the debug flag, aria-describedby, and the CSS container rules. `npm test` 427/427 pass and `npm run build` passes. Container-query rendering has not been checked in a browser.
