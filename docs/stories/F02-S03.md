# F02-S03: Settings backup and recovery

Feature: [F02](../features/F02.md)
Status: Done — PR #15 merged at cd1bddc after CI and affirmative Codex review
Depends on: F02-S02

## Outcome and scope

Add validated JSON export/import, persistence requests where supported and settings reset.

## Acceptance criteria

Export excludes live state and credentials; import previews/validates changes and handles versions; reset is explicit; unavailable storage remains usable with a warning; browser/installed-app storage sharing is not assumed.

## Validation and delivery

- Follow repository AGENTS.md and ADR-0001. Keep changes scoped to this story.
- Use fake mixer transports for automated tests; never automate real parameter writes.
- Run `npm test` and `npm run build` before opening a PR. Add meaningful checks for the behavior changed.
- Record automated results separately from device observations. Never mark a hardware gate passed without evidence.
- One story branch and PR; request `@codex review`, fix findings and request review of the final revision.
- Merge only with passing required checks and affirmative Codex review applicable to the final changes. Silence or a local agent self-review is not approval.
- Update story/feature/backlog status and evidence links in the story PR; do not begin the next story until this PR is merged.

## Evidence and completion

- Local JSON export includes accepted temporary definitions and excludes all received mixer state. Imports are bounded to 8 MiB before JSON parsing and pass the shared exact version-1 validator.
- Preview/confirm/cancel, synchronous disconnect/disarm, fresh-action tokens and safe rig-controller replacement preserve identity/target after late reads or save completions.
- Normal reset retains app caches, offline version history and sibling data. Deliberate empty records stay empty after reload, including if legacy key removal fails. Corrupt/newer/conflicted durable data is never forcibly deleted; temporary recovery is clearly labelled and destructive unknown-version recovery is parked.
- Storage protection is feature-detected/read on startup; permission is requested only by an explicit button. Denial/error remains usable without storage guarantees.
- `npm test`: 77 passed, including 12 new recovery app/actual-IDB cases. `npm run build`: passed with eight assets, worker `f06247a2bdfa6b31`. No real mixer access; accepted mockup unchanged.

All assets verified; actual file export/import roundtrip preserved ordered definitions exactly and names remained literal text (no injected nodes).
