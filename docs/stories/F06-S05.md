Status: Merged — [PR #68](https://github.com/johnsherlock/mixmate/pull/68), merge `c1bfe3f` (2026-11-22), final approved head `de5e387`; review and live record: https://github.com/johnsherlock/mixmate/pull/68#issuecomment-7065042504 (app 0.9.0)

## User request (2026-11-21)

"We're missing the high/low pass filter in the EQ. See the demo app and native ui." Filter writes on AUX outputs are authorized for this story.

## Evidence (root, desk Ui24R 192.168.0.60, firmware 3.0.7865-ui24, 2026-11-21)

Full record in the [EQ contract](../iem-aux-eq-contract.md#f06-s05-aux-eq-filters--2026-11-21). In short: each AUX output has `a.<n>.eq.hpf` and `a.<n>.eq.lpf` (`SETD`, numeric 0–1; SPARE AUX 9/10 read hpf 0, lpf 1, bypass 0, linked 0); the desk-served `mixer.html` maps `round(20 × 1000^v)` Hz, shows OFF at hpf 0 / lpf 1, and native `resetGraphEQ` sets hpf 0, lpf 1 and all peaks 0.5; root wrote four filter values, a second socket received all four echoes within 16 ms (the writer received none, as for levels/GEQ), and restoring left the 6649-key dump identical to baseline. Untested: filter slope (no AUX GEQ slope path), behaviour on a mono output.

## Decisions (root; also in [follow-ups](../user-follow-up.md))

1. **Allowlist.** Adds `3:::SETD^a.<0..9>.eq.hpf^<value>` and `3:::SETD^a.<0..9>.eq.lpf^<value>`, strict finite numeric 0..1, only through `createAuxControlSession` and the private owner's typed GEQ scope. The public API takes a typed intent `{filter, enabled, value}` (`setEqFilter`, `previewEqFilterGesture`), never paths or raw arrays. Mono output: one path. Verified reciprocal pair: both sides equally; unequal or unreceived sides keep the filters read-only with a reason while the bands stay editable. Still excluded: `eq.bypass`, slopes, `m.*` main-mix filters, input EQ, presets, AFS, native `resetGraphEQ`.
2. **Semantics.** Off = hpf exactly 0 / lpf exactly 1. Turning a cut on writes the last used position for that output in this mount, else the Demo defaults (Low cut 35 Hz, High cut 16 kHz). While enabled the position is clamped inside (0.01, 0.99) (about 20.9 Hz to 19.1 kHz) so a drag can never turn it off, and hpf stays at least 0.1 position (about one octave) below lpf. The gap is applied by the private owner against the other filter's requested position; if there is no room (for example lpf requested while hpf is at 0.95) the request is refused and nothing is sent. Hz uses the native formula; displayed values are received, a requested drag value is shown distinct until confirmed, as for GEQ.
3. **UI (Demo/prototype).** Live EQ sidebar: "Low cut" / "High cut" toggle buttons (`aria-pressed`) replace the old "Shelves / cuts: unverified" note. A cut that is on shows a draggable LC / HC handle with its frequency and a dashed vertical line; mouse, touch and pen via the handle's own r=24 hit circle (the `<svg>` stays `touch-action:none`, F09-S10); handles are focusable, Left/Right (and Down/Up) step 1/62 of the log range (Shift 4×), keyup commits, Escape cancels, Enter/Space turn the cut off. Streaming uses the GEQ cadence and budgets. Received filter values bend the displayed received line and dots with the Demo's −12 dB/oct roll-off, an approximation noted only under `?debug`.
4. **Native changes.** A filter value changed by another client stops an active gesture (no rollback) and updates the display. Own-echo classification is the same 2.5 s / 10-significant-digit rule. A changed filter outside the owned scope (unreceived or unequal pair) cancels obsolete intent so the next gesture rebuilds the scope.
5. **Reset (↺).** Keeps the immediate GEQ band reset and also writes hpf 0 / lpf 1 in the same deliberate one-shot (Demo "Active EQ reset · cuts off", native `resetGraphEQ` semantics, without calling it). Sparse: a cut that is already off sends nothing.
6. **Busy.** Filter gestures and pending sends use the same `control.gestureActive` / `pending` / `dispatching` flags `updateBusy` already counts (tested).
7. **Version.** 0.9.0 (feature) with a CHANGELOG entry.

## Implementation notes

- The filter paths join the existing `geq` control scope as members after the bands (order: hpf of every side, then lpf of every side) only when every filter path has received readback and receipt and a reciprocal pair holds exactly equal values. The reducer, own-echo journal, sparse (≥ 1e-9 and 10-significant-digit) plan, per-ordinal revalidation, throttle (leading step, ≤ 1 per max(120 ms, paths × 1000 / 250)), backpressure deferral and release-only-if-different commit are reused unchanged. The preview vector is 31 bands, plus hpf and lpf when the scope has filters. A band gesture keeps the gesture-start filter coordinate; a filter gesture keeps the gesture-start band coordinate, so neither writes the other's paths.
- `parseAuxEqStateFrame` now parses `eq.hpf` / `eq.lpf` (0..1); the opaque processing detector no longer reports them (slopes, `eq.hpf.freq` and everything else it reported before remain opaque and invalidating).
- New pure module `src/iem/aux-eq-filter.js` (constants, mapper, display roll-off).

## Review round 1 (PR #68 at `f9f0cb8`, independent reviewer APPROVE, no P1/P2; root live acceptance on SPARE passed)

- **P3:** cut editability came from received per-side equality, so while a streamed drag's echoes arrived side A then side B the buttons could flicker disabled and the badge flash "Cuts read-only · L/R cuts unequal". The cuts now stay editable and unflagged while this owner's cut gesture is active or its own filter send is pending/dispatching (the own-echo window) and every filter is received; the unequal reason shows only when the inequality is not explained by our own outstanding sends. No geometry change. Test: pair echo A then B during a drag keeps buttons enabled and the badge hidden.

## Acceptance criteria

- Exact serialization; out-of-range, non-finite, other paths, `m.*`, slopes and extra fields rejected.
- Mono one path; pair both sides equal; unequal read-only; missing filters read-only with bands unaffected.
- On/off 0/1, defaults, clamps, gap and no-room refusal.
- Streaming throttle, backpressure, sparse and release-only-if-different; own echo keeps the gesture, any other change stops it with no rollback.
- Reset writes bands plus hpf 0 / lpf 1 (both sides of a pair) and nothing when already flat and off.
- UI toggles, handles (mouse/touch/pen, keyboard), compact read-only reasons, text-only rendering, `updateBusy`, static send-site audit.
- Live acceptance (root, parked until run): toggle and drag the cuts on SPARE AUX 9/10 and a mono output on the real desk, confirm the desk's own UI follows and that native display values match; record slope observations and restore cleanup. Slope and mono-output behaviour remain unverified until then.

## Validation

Fake transports, fake DOM and fake timers only; the desk was not contacted by this story. New `tests/f06-s05-eq-filters.test.js` (22 tests). Existing tests changed only where behaviour deliberately changed: the receive-parser admits `eq.hpf` / `eq.lpf`; the GEQ runtime fixture sends hpf 0 / lpf 1 as the real desk does; the "unverified shelves / cuts" note assertion became the cut bank; the build test's expected version. `npm test` 583/583 (561 before); `npm run build` passes.

## Risks and unverified

Filter slope and DSP centre response are not verified (the drawn −12 dB/oct roll-off is an approximation); mono-output behaviour untested on the desk; the gap (0.1) and the 0.01 / 0.99 bounds are product choices, not desk limits (the desk accepts the full 0..1 range); native clients changing a filter during a gesture stop it by design. Physical device qualification remains F08-S01.
