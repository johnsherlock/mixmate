This resolves the F06-S04 review P3 ("a planned value equal to the desk value gets no receipt") and the reconnect requirement of the GEQ basis barrier. Own-echo matching and native cancellation are unchanged; nothing is replayed. See [ADR-0008](adr/0008-control-state-model.md#f09-s06-amendment--2026-11-19).
- **Points saturate at ±15 dB per band (2026-11-19 change from root's live finding: "points saturate at ±15 per band; never reject whole").** The first F09-S06 head clamped the dragged point's gain so every band stayed in range; live on SPARE that blocked point 2 (≈1 kHz) entirely once point 1 had pushed the 100 Hz bands to +15, because point 2's small Gaussian tail there left no headroom ("Unchanged requested coordinate"). Now `requestedPointSamples` saturates each band the bump would push past the range at exactly ±15 dB (one-sided: a band at +15 stays at +15 for a positive bump and can still move inward); other bands follow the points; untouched bands keep exact basis values. The dragged handle always follows horizontally and follows vertically until its own centre reaches ±15 (`pointCentreGainLimit`, widened by the point's current gain so a neighbour that already pushed the centre past the limit never pulls the gain inward; the point Δ itself stays within ±12). The dashed requested curve shows the saturated values. The session's unchanged range check always passes and the session itself still rejects, never clips, an out-of-range curve (draw mode is unchanged and cannot leave the range).

## Verified GEQ-only contract — pure implementation, runtime unwired

- Pure typed output-band form: `3:::SETD^a.<0..9>.eq.peak.<0..30>^<value>`, strict finite numeric0–1, no arbitrary paths/fields, raw arrays or input/main fallback. Use full finite command precision unless later evidence requires a wire quantization policy. Typed plans must expect the exact serialized value. Read-only `a.N.eq.bypass` is a received0/1 boolean prerequisite/status; it grants no bypass-write capability.
- Require owned current Ui24 model, explicit AUX mode, mono or reciprocal non-conflicting output link metadata and every band's actual received value on each side, with receipt evidence. A linked pair has31 paths per side; preserve both raw profiles and block control when unequal instead of silently equalizing. No main `.eq.peak.l/r`, source EQ, gain, AFS, routing, preset metadata, HPF/LPF, filter slope, bypass or shelf write forms.
- Freeze a complete current profile/context for one explicit gesture. Generation, target/selection/profile, AUX/matrix/link, EQ/native-processing changes invalidate; an external away-and-back edit must not hide behind equal final values. Future owner-closed context revisions and per-path receipt counters are required. Opaque latest-intent ordered plans revalidate before every authorization. Partial fresh echoes after complete dispatch remain pending until every required path matches; conflicting/new native state stops/disarms. Exact send-return/deadline/reentrant-stop behavior must reuse the established runtime safety policy in S04. No retry/rollback/replay or incoming-triggered sends.
- Pure requested curve is separate from received bands: finite bounded ordered log-frequency samples, evaluated at the31 native display centres; reject a requested band outside±15dB rather than silently clipping independent bands. Point/draw modes remain distinct UI intents in S04, with no reverse fitting of native bands into three points. Actual per-side band readback remains authoritative after native changes; a connected line through band values is not a proven DSP response.
- Reset proposal: only the selected verified31-band GEQ profile(s) to.5, with the same full baseline/arming/readback guards. Preserve bypass/filter/AFS/dynamics/preset fields; do not call native `resetGraphEQ`. No blanket native reset is authorized by this proposal.
- Dedicated shelves remain **unverified/parked**. Manual/native HPF/LPF are separate filters, not shelves and not a silent replacement for mock cuts. The accepted mapping may proceed with verified GEQ-only scope later, with explicit limitations; no dedicated shelf/cut control or phantom parametric DSP is enabled here. Physical DSP centres/response, firmware precision, field coverage, native edits and link mirroring/fresh echoes remain F08 qualification.

**Requested curve versus actual.** Both modes start from the gesture's *editable basis*: the session coordinate frozen at gesture start (received bands at arm, or the last requested vector while the desk has not echoed it, per ADR-0008; that requested curve is shown dashed). Points mode (revised after PR #49 review): three points (log-frequency position, Δ gain ±12 dB, normalized narrowness) form a smooth bump sum that is **added to the basis** at the 31 display centres — a relative adjustment, never an inverse fit and not parametric hardware. Bands whose bump is below 0.001 dB send the basis dB unchanged; since F09-S06 (2026-11-19 live finding) a points band the bump would push past ±15 dB saturates at exactly ±15 dB (one-sided; never rejected whole), while draw curves and the session still reject an out-of-range request whole with a visible status, never clipped. An all-zero Δ release is a no-op, and point gains return to 0 dB Δ after every release, cancel or native-change cancellation, so a later gesture never re-applies an old bump. Draw mode redraws per-band values from the same basis. In both modes a band whose dB equals the seed's exact `auxEqPositionToDb` value keeps the seed's raw coordinate, so unedited bands never drift through a dB round trip. Modes are mutually exclusive; switching cancels without writes. Requested curves (dashed) and per-side received band values (dots/solid line, both sides when unequal) are drawn separately, with a visible note that centres are display labels and lines are not measured response. L (filled green) and R (hollow magenta) received sides are drawn with distinct labelled colours when unequal; equal sides show one line labelled L=R. ### Observed firmware behaviour — 3.0.7865-ui24, 2026-11-18 (root live check on PR #49 head `18b096f`)

Attributed to this firmware/build and target (desk 192.168.0.60, reciprocal AUX pair a.8/a.9); not generalized. A points Δ +0.1 dB release sent 62 SETD (a.8 then a.9, about 17 ms).
