# Mixmate

An offline PWA testing Soundcraft Ui24R connectivity on Android and iOS.

- This is a separate project from solartracker.
- Keep all application assets bundled locally; no runtime CDNs, analytics or accounts.
- Runtime transport permits `3:::INIT`, `3:::ALIVE`, `2::`, the validated input `.mix` form only in the existing explicitly armed input-fader test, and the exact typed AUX level forms below only through `createAuxLevelSession` or `createAuxControlSession`. The separate `createReadOnlySession` factory still exposes only the three connection messages and cannot be upgraded by options; never broaden that factory or call the input writer for AUX controls.
- F05-S01 deliberately adds reviewed typed AUX-level serializer forms: `3:::SETD^a.<0..9>.mix^<value>` and `3:::SETD^<source>.aux.<0..9>.value^<value>`, source i.0..23/l.0..1/p.0..1/f.0..3, JavaScript finite numeric value 0..1 inclusive. F05-S02 integrates these forms only through the privately owned typed AUX-control session, explicit current-target arming, opaque release/keyup gesture token, owned current-socket/generation/selection state, received Ui24/AUX-mode/link/level prerequisites and per-command revalidation. No per-move or incoming-triggered sends. Confirmation requires fresh per-path readback within 2.5 seconds; pending blocks new gestures, interruption stops/disarms without rollback/retry/replay, and a matching observation is not a correlated acknowledgement. The [individual control contract](docs/iem-aux-level-controls.md) defines dispatch/readback/context rules. No arbitrary path/raw sender, guessed fallback or AUX-to-input `.mix` substitution. See [ADR-0004](docs/adr/0004-aux-level-safety.md) and the [exact contract](docs/iem-aux-level-safety.md). Unequal linked target levels remain read-only; relative groups use only canonical saved membership for the bound stable profile/current AUX, one frozen finite non-silent baseline, deduplicated source × output paths and one common delta clamped at the first member limit. Group selection accepts IDs only, not raw member/value arrays; commit uses its opaque gesture's exact cached preview delta, not a sanitized native range value. The supported group finite window is -199 dB through the continuous profile upper endpoint (approximately +10 dB), never a replacement value for silence. See the [relative group contract](docs/iem-relative-groups.md). All other fields remain outside these level forms.
- F06-S02 deliberately integrates the reviewed normalized AUX-send pan forms `3:::SETD^<source>.aux.<0..9>.pan^<value>` only through literal `createAuxControlSession`, source i.0..23/l.0..1/p.0..1, strict finite numeric 0..1 validated before pinned three-decimal normalization. The existing `createAuxLevelSession` remains levels/groups-only; caller options cannot upgrade either legacy factory. Eligibility requires current Ui24 model, explicitly mono non-conflicting source, reciprocal stereo outputs both in AUX mode and actual equal pan observations on both paths. Mirror the same source across outputs only, never level-style source Cartesian fan-out. No FX/linked-source balance, mono-AUX pan, AUX-master/input/main pan or raw-path fallback. Numeric direction/L/R/Centre labels remain unverified; use normalized numbers only. Pan/level/group selection, arming, gesture and pending operation share mutually exclusive private ownership. Explicit Enable pan and opaque release/keyup or deliberate numeric preset intent are required; expected readback is the actual wire-rounded value. Apply the same current-generation/per-path fresh receipt/2.5-second deadline/reentrant partial-stop/no-retry rules. Dialog replacement, closing, context/native changes and hiding cancel/disarm; never restore permission from settings. See [ADR-0005](docs/adr/0005-normalized-aux-pan-safety.md), [pure pan contract](docs/iem-aux-pan-safety.md) and [runtime contract](docs/iem-pan-controls.md).
- F06-S03 permits only pure, **unwired** typed AUX GEQ-band serializer forms `3:::SETD^a.<0..9>.eq.peak.<0..30>^<value>`, strict finite numeric 0..1 with full serialized precision, and a separate bounded receive parser for those bands plus read-only `a.N.eq.bypass` 0/1. No production factory/session/UI may send EQ until separately reviewed S04 integration. No input/main/source PEQ, bypass, filter/slope, shelf, AFS, preset metadata or broad reset writes. Require privately owned current selected Ui24/AUX-mode/link metadata, all 31/62 band and bypass observations/receipts, equal raw linked profiles, frozen baseline and generation/context/native-EQ/processing revisions. Future owner must conservatively invalidate on native processing changes including unsupported fields, without guessing their semantics. Requested curves sample verified native display centres (not a DSP claim), reject outside ±15 dB rather than clipping, and stay separate from received state. Reset plans flatten only selected GEQ bands. Apply opaque latest-intent/per-ordinal cutpoint/partial readback rules; no real actuation or runtime capability change in S03. See [ADR-0006](docs/adr/0006-aux-geq-curve-contract.md) and [evidence/contract](docs/iem-aux-eq-contract.md).
- User authorization dated 2026-11-09 covers future implementation of AUX-master/send levels and relative groups, AUX pan, AUX output EQ curves mapped to verified graphic-EQ bands/supported shelves, snapshot recall/save, and multitrack start/stop. See [ADR-0002](docs/adr/0002-deferred-qualification-and-authorized-controls.md). This is feature-class authorization, not an immediate expansion of the active wire allowlist; do not request the same scope permission again.
- Before enabling an approved feature, document verified exact paths/message forms, types/ranges, capabilities, stereo handling and current-socket prerequisites, then deliberately update this active allowlist and narrow typed guards in that feature's reviewed PR. No generic sender or guessed paths. Unknown semantics remain unavailable or parked. No independent mute, gain, routing, clock/time, network, general scene-edit/delete or destructive configuration writes.
- The approved snapshot recall/save operations are the deliberate exception to the former scene-change prohibition; recall may apply the selected snapshot's stored settings. This does not authorize arbitrary parameter/configuration write paths outside the named operation.
- No real-desk actuation during development or automated verification. All automated writes use fake mixer transports; human live-actuation qualification must be separately arranged.
- Fader writes require received channel level and stereo-link metadata on the current live socket. Future approved controls require their verified current-socket capability/state prerequisites. Preserve source and output stereo-linked relationships. Never queue/retry/replay writes or write in response to incoming state. Clamp relative group moves as a whole at the first member limit; do not independently clamp members and lose balance.
- UI control starts disabled and must be enabled by the user for the selected channel. Disarm on channel change, disconnect and app hiding.
- Automated tests must use fake mixer transports for all write commands; do not move real faders.
- Connect only after a user action. Do not reconnect automatically, including after sleep or navigation.
- Do not persist mixer state. Treat mixer strings as untrusted; render them with textContent.
- Distinguish socket connectivity from receiving actual channel state. Clear displayed state when disconnected.
- Do not claim offline readiness until every precached asset is verified.
- Preserve relative paths and service worker scope under `/mixmate/` on GitHub Pages.
- Run `npm test` and `npm run build` before opening a PR.
- Request `@codex review` on PRs; resolve findings and wait for affirmative Codex review before merging. Silence is not approval.

- Per ADR-0002, F01/S03 may complete as an implementation/evidence checkpoint while physical-device qualification remains open in F08-S01. Record unsupported/untested results honestly. Work stories sequentially through reviewed PRs; when hardware blocks a story, record it as parked and document a dependency exception before independent coding. Track decisions and follow-ups in `docs/user-follow-up.md`.
