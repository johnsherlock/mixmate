# MixMate agent instructions

Offline-first Soundcraft Ui24R IEM PWA for phones/tablets. Vanilla JavaScript ES modules and Vite. The accepted `mockups/iem.html` is a design reference, not protocol evidence. No framework migration is agreed.

## Story workflow

- For a new orchestrator, start with [the handoff](docs/orchestrator-handoff.md). For story work, read [the backlog](docs/backlog.md), the assigned `docs/stories/<ID>.md`, its feature document and relevant contracts/ADRs. Historical checkpoint text is not current capability or merge evidence; inspect code and current PR state when needed.
- Preserve the master-orchestrator workflow: delegate implementation to one story agent at a time, sequentially. One `codex/` branch and PR per story; do not start the next implementation story while review is outstanding. Do not create sidebar chats unless requested.
- Run required checks, request `@codex review`, resolve findings and obtain affirmative review of the final changes plus passing checks before merging. Silence or local self-review is not approval. Confirm merge before marking a story merged.
- Update story, feature and backlog status in the story PR. Record routine decisions, unresolved findings and dependency exceptions in [user-follow-up.md](docs/user-follow-up.md). Park hardware-blocked acceptance honestly before independent work; do not waive the F08 release gate. Respect explicit user deferrals.
- Preserve existing work, including the untracked `docs/iem-integration-handoff.md`; do not stage unrelated changes. That handoff describes an early baseline, not the current allowlist.
- Follow the [orchestrator lifecycle](docs/orchestration.md): one fresh-context story agent (`fork_turns: "none"` where supported), GPT-6.1 Sol Medium, automatic progression only inside the explicitly authorized batch, and a reviewed repository handoff at the batch boundary. Check context/reliability at each story boundary; finish or safely park exact outstanding work before rotating. A fresh chat does not reset account usage limits.

## Architecture and state

- `src/iem/` owns the live IEM app. `index.html` and `iem.html` use the same live entry; `demo.html` is isolated simulation. `connection-test.html` / `src/main.js` preserve the separate input-fader experiment. Never import demo state or input writers into AUX control.
- `session-core.js` privately owns sockets, observations, receipts, generations and control intent. Public snapshots/presentation Maps do not grant authority. Literal factories cannot be upgraded by options; do not grant runtime send authority through generic senders or caller-supplied raw path/value arrays.
- Use bounded receive parsers; missing metadata is unknown, not mono/default state. Distinguish socket-open, received Ui24/AUX readiness and meter freshness. Clear received state on disconnect. Render mixer/user strings with `textContent`.
- Settings/groups are device-local definitions via `src/settings.js`, not mixer state; there is no settings export/import UI (removed by user decision 2026-11-20, F09-S08). Bind groups to stable saved profile IDs; matching an IP does not establish rig identity. Manual address connections do not bind a saved rig. Preserve unresolved member IDs, explicit save/conflict/temporary status and transaction-commit semantics. Never persist live values, arming, baselines or pending operations. See [settings](docs/settings-repository.md) and [groups](docs/iem-groups.md).
- Preserve keyed strip/input/cap nodes across updates and the accepted touch behavior: cap drag, double-track jump, single track touch/swipe scrolls without writing. Keep phone portrait three-column banks and compact landscape travel. See [presentation](docs/iem-presentation.md) and the relevant control contract before changing gesture/dialog ownership.

## Active transport boundary

Read the linked contracts before changing serializers, guards or dispatch. Feature-class authorization in [ADR-0002](docs/adr/0002-deferred-qualification-and-authorized-controls.md) does not enable unimplemented wire commands; do not ask for that same scope approval again. New runtime capability needs verified exact forms/types/ranges, stereo/current-socket prerequisites and a deliberate allowlist/typed-guard update in its reviewed PR.

| Capability | Permitted boundary and required contract |
| --- | --- |
| Connection-only | `createReadOnlySession`: only `3:::INIT`, `3:::ALIVE`, `2::`; never upgrade this factory. |
| Input test | Validated `3:::SETD^i.<0..23>.mix^<value>` only in the separate explicitly armed experiment; never substitute for AUX sends. |
| AUX levels/groups | `createAuxLevelSession` or `createAuxControlSession`: `3:::SETD^a.<0..9>.mix^<value>` and `3:::SETD^<source>.aux.<0..9>.value^<value>`, sources i.0..23/l.0..1/p.0..1/f.0..3, strict finite numeric 0..1. Live level faders show a dB-linear display scale (user decision 2026-11-19, F09-S06; floor −70 dB by user decision 2026-11-20, F09-S07: +10…−70 dB linear, short bottom segment to −∞; wire value stays the desk position). Group fader (user decision 2026-11-20, F09-S08): one common delta in display-scale units (equal dB = equal distance above −70 dB; equal on-screen distance in the bottom segment); cap = loudest member's displayed level; top = loudest at 1, bottom = quietest at position 0 (−∞); a member already at −∞ is a valid finite anchor (it can rise) but allows no further downward travel; groups may write position 0. [Level safety](docs/iem-aux-level-safety.md), [runtime](docs/iem-aux-level-controls.md), [relative groups](docs/iem-relative-groups.md). |
| AUX send pan | Only `createAuxControlSession`: `3:::SETD^<source>.aux.<0..9>.pan^<value>`, sources i.0..23/l.0..1/p.0..1, strict finite numeric 0..1 before three-decimal normalization. Mono source into verified reciprocal stereo AUX pair with equal actual pan; mirror the same source across outputs only. No linked-source/FX balance. Display-only L/CENTRE/R labels (user decision 2026-11-20, F09-S09): wire 0 = `L 100`, 0.5 = `CENTRE`, 1 = `R 100`, linear integer, as the Demo; wire values unchanged; physical direction verified on the desk by root. [Pan safety](docs/iem-aux-pan-safety.md), [runtime](docs/iem-pan-controls.md). |
| AUX GEQ | Only `createAuxControlSession`: `3:::SETD^a.<0..9>.eq.peak.<0..30>^<value>`, strict finite numeric 0..1, full precision, through the private owner's typed scope allowlist: sparse, up to 31/62 changed band paths (mono / verified reciprocal pair with exactly equal raw bands/bypass); bands within 1e-9 of the last requested value are not sent; streamed live during a gesture since F09-S05. Public API takes points/draw curve intent or scoped reset, never paths or raw arrays; since F09-S07 (user decision 2026-11-20) points are persistent Demo-style drawing aids (x/gain/q) over an in-memory anchored base, re-anchored at 0 dB on open, draw/reset or any outside change; points saturate at ±15 dB per band, never reject whole (2026-11-19 live finding), while the session still rejects, never clips, an out-of-range curve. `eq.bypass` and unmodelled output processing are receive-only (displayed/invalidating); no bypass/filter/shelf/AFS/preset/main-L/R/input-EQ writes and never native `resetGraphEQ`. Display centres are not verified DSP centres. [EQ contract](docs/iem-aux-eq-contract.md), [ADR-0006](docs/adr/0006-aux-geq-curve-contract.md), [runtime](docs/iem-control-runtime.md). |

- After explicit connection, qualified controls accept direct cap/key gestures without prior selection or Enable/Disable. The private owner establishes opaque per-gesture authority automatically. **Live writes (user decision 2026-11-18, [ADR-0008 F09-S05](docs/adr/0008-control-state-model.md#current-f09-s05-live-write-decision--2026-11-18)):** while an owned deliberate cap/key/preset gesture is active, level/group/pan/GEQ stream the latest cached preview through the same private per-ordinal guard, throttled (leading step, then ≤1 step per max(50 ms — GEQ 120 ms —, paths × 1000 / budget) with budgets 100 SETD/s level/pan, 200 group, 250 GEQ; deferred while writer `bufferedAmount` > 4096 B; latest value wins, no queue) and sparse (only paths ≥1e-9 from the last requested value); release/keyup sends the final exact value only if it differs. GEQ reset is an immediate deliberate one-shot (user decision 2026-11-20, F09-S09). Never incoming-, selection- or scroll-triggered writes; single track touch/swipe never begins a gesture. A companion receipt equal (exactly or at the desk’s observed 10-significant-digit echo format) to a value this owner sent for that path within the 2.5 s window and not yet superseded is an own echo and never cancels; any other changed value is native and stops the stream immediately with no rollback/replay. Cancel after live steps leaves the streamed values applied and says so. Selection/context/native changes cancel obsolete intent; the next deliberate gesture uses current compatible actual without manual rearm. Hiding/disconnect clear received state. Connect only by explicit user action; no background probing or automatic reconnect after sleep/navigation.
- Preserve source/output stereo relationships and actual individual readbacks; unequal linked targets stay read-only. Relative groups use canonical saved membership, a fresh immutable finite received anchor for each gesture (silent members included since F09-S08), deduplicated paths and one requested delta clamped at the first member limit (top: loudest at max; bottom: quietest at the floor); each explicit gesture starts at local delta zero and member strips preview the requested values distinctly from received actual. Commit the exact cached common preview, not a sanitized range value. Requested offsets do not prove actual hardware balance.
- Level/group/pan/GEQ use the privately integrated [ADR-0008 peer-editor model](docs/adr/0008-control-state-model.md#current-f09-s04-peer-editor-decision--2026-11-17). Each explicit control connection owns a typed writer and receive-only companion; only companion INIT/ALIVE/heartbeat observations populate actual/provider/meter state, never late writer INIT. Both sockets must be current/open; either failure/lifecycle timeout clears/closes both, no automatic reconnect. The literal read-only factory stays single connection. All-returned sends have bounded 2.5-second exact-fresh observation diagnostics, never ACK; an explicit absolute gesture may supersede pending immediately and equal retained requested vectors are no-ops. Groups use fresh finite actual anchors per gesture (never while own echoes are outstanding), and overlapping prior local writes require every original component path's newer actual receipt after its preauthorization cutpoint before rebasing — bounded since F09-S06 by the 2.5 s observation window from the last write: the desk drops echoes for equal re-sends and sub-5 ms reversals, so after the window the received value is the desk's actual and the next gesture (group or GEQ) rebases on it with a plain "desk did not report" status (no invented receipt, replay or requested-as-actual). Incomplete-dispatch recovery barriers are not time-bounded. Rounded/native receipts provide actual basis without implying request success. Incomplete/reentrant/unknown dispatch retains full original touched-closure strictly post-invalidation-floor recovery, covering unattempted paths; subset/selection/topology changes cannot erase it. Complete compatible recovery allows a new gesture automatically, without Enable. Revalidate writer/receiver/socket/topology/canonical settings before every ordinal and exact authorization after reducer clock checks; any synchronous reentrant relevant value receipt stops remainder. Settle exact outstanding outcome IDs after reentrancy; no rollback/queue/retry/replay. Received values remain raw and distinct from requested, with no numerical tolerance concealing native edits beyond the explicit own-echo match. Within a begun gesture, preview/step/commit revalidate topology only (linked own echoes arrive as separate receipts); begin keeps the full check. Multi-write hardware application/balance/causality remains unguaranteed.
- **Observed interoperability issue:** bounded 2026-11-11 trials applied level/pan writes but received no sender-path echoes; explicit fresh connection showed changed values. The old-build timeout disarmed while the socket stayed live; revised S04 uses a receive-only companion and automatic qualified editing, with exact-build evidence tracked separately. Do not generalize this to every firmware or replace received state with sent intent. [F08-S03](docs/stories/F08-S03.md) and the follow-up log separate evidence from untested hypotheses and track the unresolved readback design.
- All other write fields remain outside the allowlist: no independent mute/gain/routing/clock/network, arbitrary scene edits/deletes or destructive configuration. Future approved snapshot recall/save is the named exception allowing the selected snapshot's stored settings, not arbitrary parameter writes; recording/snapshots remain unwired until reviewed implementation.

## Offline and verification

- Bundle all runtime assets locally: no runtime CDNs, analytics or accounts. Preserve relative paths and `/mixmate/` manifest/service-worker scope on GitHub Pages. Offline-ready requires verified inventory **and current-entry/asset proof**; a generic old-worker reply is insufficient. No forced update/reload during a session. See [distribution audit](docs/distribution-audit.md).
- Node 24 (CI); `npm ci`, `npm test`, `npm run build`. Both tests and build are required before a PR. `npm run dev` has no generated offline worker; use `npm run build` then `npm run preview` for production/offline QA. The build emits four entries, copies the reference and generates the verified precache; do not hand-edit generated `dist/` assets.
- All automated write tests use fake mixer transports. The user’s standing 2026-11-17 permission authorizes necessary live desk/native-app edits and interruption/recovery checks inside the explicitly authorized story; record actual targets/changes/method/results/cleanup without repeated gesture/time-window approvals. This does not authorize unrelated stories, new write classes or agent snapshot save/recall/delete. Never weaken browser security or change mixer/router configuration to make a check pass.
- Report changed behavior, checks run/results, build/device context for browser/live evidence, remaining risks and parked acceptance. Separate source-backed semantics, fake-test results, observed firmware/device behavior and hypotheses. Desktop/emulation or one tablet connection does not certify Android/iOS/offline/sleep support; [F08-S01](docs/stories/F08-S01.md) remains the physical qualification gate.
