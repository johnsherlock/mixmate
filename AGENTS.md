# MixMate agent instructions

Offline-first Soundcraft Ui24R IEM PWA for phones/tablets. Vanilla JavaScript ES modules and Vite. The accepted `mockups/iem.html` is a design reference, not protocol evidence. No framework migration is agreed.

## Story workflow

- For a new orchestrator, start with [the handoff](docs/orchestrator-handoff.md). For story work, read [the backlog](docs/backlog.md), the assigned `docs/stories/<ID>.md`, its feature document and relevant contracts/ADRs. Historical checkpoint text is not current capability or merge evidence; inspect code and current PR state when needed.
- Preserve the master-orchestrator workflow: delegate implementation to one story agent at a time, sequentially. One `codex/` branch and PR per story; do not start the next implementation story while review is outstanding. Do not create sidebar chats unless requested.
- Run required checks, request `@codex review`, resolve findings and obtain affirmative review of the final changes plus passing checks before merging. Silence or local self-review is not approval. Confirm merge before marking a story merged.
- Update story, feature and backlog status in the story PR. Record routine decisions, unresolved findings and dependency exceptions in [user-follow-up.md](docs/user-follow-up.md). Park hardware-blocked acceptance honestly before independent work; do not waive the F08 release gate. Respect explicit user deferrals.
- Preserve existing work, including the untracked `docs/iem-integration-handoff.md`; do not stage unrelated changes. That handoff describes an early baseline, not the current allowlist.
- Follow the [orchestrator lifecycle](docs/orchestration.md): one fresh-context story agent (`fork_turns: "none"` where supported), GPT-6.1 Sol Medium, automatic progression only inside the explicitly authorized batch, and a reviewed repository handoff at the batch boundary. Check context/reliability at each story boundary; finish or safely park exact outstanding work before rotating. A fresh chat does not reset account usage limits.

## Architecture and state

- `src/iem/` owns the live IEM app. `index.html` and `iem.html` use the same live entry; `demo.html` is isolated simulation. `connection-test.html` / `src/main.js` preserve the separate input-fader experiment. Never import demo state or input writers into AUX control.
- `session-core.js` privately owns sockets, observations, receipts, generations and control intent. Public snapshots/presentation Maps do not grant authority. Literal factories cannot be upgraded by options; do not grant runtime send authority through generic senders or caller-supplied raw path/value arrays.
- Use bounded receive parsers; missing metadata is unknown, not mono/default state. Distinguish socket-open, received Ui24/AUX readiness and meter freshness. Clear received state on disconnect. Render mixer/user strings with `textContent`.
- Settings/groups are device-local definitions via `src/settings.js`, not mixer state. Bind groups to stable saved profile IDs; matching an IP does not establish rig identity. Manual address connections do not bind a saved rig. Preserve unresolved member IDs, explicit save/conflict/temporary status and transaction-commit semantics. Never persist live values, arming, baselines or pending operations. See [settings](docs/settings-repository.md) and [groups](docs/iem-groups.md).
- Preserve keyed strip/input/cap nodes across updates and the accepted touch behavior: cap drag, double-track jump, single track touch/swipe scrolls without writing. Keep phone portrait three-column banks and compact landscape travel. See [presentation](docs/iem-presentation.md) and the relevant control contract before changing gesture/dialog ownership.

## Active transport boundary

Read the linked contracts before changing serializers, guards or dispatch. Feature-class authorization in [ADR-0002](docs/adr/0002-deferred-qualification-and-authorized-controls.md) does not enable unimplemented wire commands; do not ask for that same scope approval again. New runtime capability needs verified exact forms/types/ranges, stereo/current-socket prerequisites and a deliberate allowlist/typed-guard update in its reviewed PR.

| Capability | Permitted boundary and required contract |
| --- | --- |
| Connection-only | `createReadOnlySession`: only `3:::INIT`, `3:::ALIVE`, `2::`; never upgrade this factory. |
| Input test | Validated `3:::SETD^i.<0..23>.mix^<value>` only in the separate explicitly armed experiment; never substitute for AUX sends. |
| AUX levels/groups | `createAuxLevelSession` or `createAuxControlSession`: `3:::SETD^a.<0..9>.mix^<value>` and `3:::SETD^<source>.aux.<0..9>.value^<value>`, sources i.0..23/l.0..1/p.0..1/f.0..3, strict finite numeric 0..1. [Level safety](docs/iem-aux-level-safety.md), [runtime](docs/iem-aux-level-controls.md), [relative groups](docs/iem-relative-groups.md). |
| AUX send pan | Only `createAuxControlSession`: `3:::SETD^<source>.aux.<0..9>.pan^<value>`, sources i.0..23/l.0..1/p.0..1, strict finite numeric 0..1 before three-decimal normalization. Mono source into verified reciprocal stereo AUX pair with equal actual pan; mirror the same source across outputs only. No linked-source/FX balance or direction labels. [Pan safety](docs/iem-aux-pan-safety.md), [runtime](docs/iem-pan-controls.md). |
| AUX GEQ | Pure **unwired** serializers only: `3:::SETD^a.<0..9>.eq.peak.<0..30>^<value>`, strict finite numeric 0..1, full precision. No production factory/session/UI sends EQ before separately reviewed integration. GEQ-only reset; no bypass/filter/shelf/AFS/preset writes. Display centres are not verified DSP centres. [EQ contract](docs/iem-aux-eq-contract.md), [ADR-0006](docs/adr/0006-aux-geq-curve-contract.md). |

- Controls start off; explicitly arm the selected eligible target. Commit only deliberate release/keyup or supported preset intent through opaque owned gestures, never per-move or incoming-triggered writes. Selection/context/native changes, hiding and disconnect cancel/disarm. Connect only by explicit user action; no background probing or automatic reconnect after sleep/navigation.
- Preserve source/output stereo relationships and actual individual readbacks; unequal linked targets stay read-only. Relative groups use canonical saved membership, a frozen finite non-silent baseline, deduplicated paths and one common delta clamped at the first member limit; commit the exact cached preview delta, not a sanitized range value.
- Current level/pan confirmation requires fresh per-path receipt after authorization within 2.5 seconds. Pending blocks gestures; interruption stops/disarms without rollback, queue, retry or replay. Multi-write dispatch is non-atomic. Matching observations are not correlated acknowledgements; send return is not confirmation.
- **Observed interoperability issue:** bounded 2026-11-11 trials applied level/pan writes but received no sender-path echoes; explicit fresh connection showed changed values. Timeout disarmed while the socket stayed live. Do not generalize this to every firmware or replace received state with sent intent. [F08-S03](docs/stories/F08-S03.md) and the follow-up log separate evidence from untested hypotheses and track the unresolved readback design.
- All other write fields remain outside the allowlist: no independent mute/gain/routing/clock/network, arbitrary scene edits/deletes or destructive configuration. Future approved snapshot recall/save is the named exception allowing the selected snapshot's stored settings, not arbitrary parameter writes; recording/snapshots remain unwired until reviewed implementation.

## Offline and verification

- Bundle all runtime assets locally: no runtime CDNs, analytics or accounts. Preserve relative paths and `/mixmate/` manifest/service-worker scope on GitHub Pages. Offline-ready requires verified inventory **and current-entry/asset proof**; a generic old-worker reply is insufficient. No forced update/reload during a session. See [distribution audit](docs/distribution-audit.md).
- Node 24 (CI); `npm ci`, `npm test`, `npm run build`. Both tests and build are required before a PR. `npm run dev` has no generated offline worker; use `npm run build` then `npm run preview` for production/offline QA. The build emits four entries, copies the reference and generates the verified precache; do not hand-edit generated `dist/` assets.
- All automated write tests use fake mixer transports. Do not actuate real hardware during development unless separately and explicitly authorized for a bounded live check; the earlier diagnostic exception is not blanket test permission. Never weaken browser security or change mixer/router configuration to make a check pass.
- Report changed behavior, checks run/results, build/device context for browser/live evidence, remaining risks and parked acceptance. Separate source-backed semantics, fake-test results, observed firmware/device behavior and hypotheses. Desktop/emulation or one tablet connection does not certify Android/iOS/offline/sleep support; [F08-S01](docs/stories/F08-S01.md) remains the physical qualification gate.
